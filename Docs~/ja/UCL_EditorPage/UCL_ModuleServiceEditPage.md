# UCL_ModuleServiceEditPage (モジュールサービス編集ページ)

## 1. ページ概要
`UCL_ModuleServiceEditPage` は、UCL モジュールシステムの中心的な管理インターフェースです。開発者はここで、編集モードの切り替え、モジュール設定の管理、新規モジュールの作成、およびプレイリスト管理ワークフローへのアクセスを行うことができます。

## 2. 主要な機能ブロック

### 2.1 グローバル管理
*   **編集モード (Edit Mode)**: システムが動作するリソース環境を切り替えます。
    *   `Builtin`: 内部モジュールを処理します（通常は `StreamingAssets` 内）。
    *   `Runtime`: 実行時モジュールを処理します（`PersistentDataPath` 内、Modding をサポート）。
*   **設定操作**: 「Save Config」(設定保存) および 「Load Config」(設定読み込み) 機能を提供します。
*   **パスへのアクセス**: 「Open Module Folder」(モジュールフォルダを開く) ボタンにより、物理ファイルへの素早いナビゲーションが可能です。

### 2.2 モジュールのメンテナンス
*   **新規モジュール作成**: まったく新しいモジュールフォルダと設定を構築します。
*   **モジュール編集エントリ**:
    *   ポップアップメニューからターゲットのモジュール ID（例：`Core`）を選択します。
    *   **「編集」** ボタンをクリックして、そのモジュールの詳細設定ページ (`UCL_ModuleEditPage`) に入ります。

### 2.3 プレイリスト管理 (Playlist Management)
*   **プレイリスト編集**: ボタンをクリックして `UCL_ModulePlayListPage` を開きます。
*   **動作ロジックのヒント**: 特定のモジュールを有効にするには、プレイリストに追加する必要があります。モジュールはプレイリストで定義された順序でロードされます。**後からロードされたモジュールは、以前のモジュールと同じ ID を持つアセットを上書きします**。

### 2.4 実行時の状態確認
*   **現在ロードされているモジュール**: 展開して、システム内でアクティブなモジュールインスタンスを確認できます。
*   **AssetsCache**: アセットキャッシュ辞書の状態を表示し、パス解決のデバッグに役立ちます。

## 3. 注意事項
> [!WARNING]
> `Builtin(Core)` への直接の編集は、システムアップデート後に失われる可能性があります。内容を追加または上書きするには、新しいモジュールを作成することをお勧めします。

> [!TIP]
> 「複製」(Copy) ボタンを使用すると、現在のページのデータパスを素早く取得でき、スクリプトでのデバッグが容易になります。
