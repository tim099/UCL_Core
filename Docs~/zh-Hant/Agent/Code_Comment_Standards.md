# 程式碼註解規範

> 本文件是跨專案共用的程式碼註解規範。各 consumer repo 可在自己的 agent 入口補充專案限定規則，但不得在此複製專案內容。

## 1. 區塊起始說明（三段式）

在每個程式碼區塊的起始處，**必須**說明三件事：

| 欄位 | 回答什麼 |
|---|---|
| **區塊職責** | 這段在做什麼（一句話講清楚範圍） |
| **物理意義** | 對應到現實／遊戲中的什麼概念（為什麼要這樣算） |
| **數值影響** | 改了會怎樣（影響哪些數值、有無副作用、是否唯讀） |

```csharp
// 區塊職責：繪製圖層的採樣數值資訊
// 物理意義：將 GPU 採樣回來的 0~1 顏色值轉換回實際物理量並顯示，包含主圖層與關聯的次要圖層。
// 數值影響：無修改，僅作視覺化呈現，方便開發者比對物理狀態。
```

> [!NOTE]
> 三段式的價值在**第三段**：「數值影響」逼作者說清楚副作用範圍。
> 只寫「這段畫 UI」等於沒寫 —— 讀的人要知道的是「我改它會壞什麼」。

## 2. 參數註解格式（`///` XML 文件註解）

公開欄位、屬性、方法一律用 `///`：

```csharp
/// <summary>
/// 模擬運算所需的物理參數 (Shader Uniforms)。
/// 這些值將由 ClimateSim 自動上傳至 ComputeShader 的對應 Float 變數。
/// </summary>
public List<FloatValueAssetEntry> shaderParams = new();
```

## 3. 決策與血證要寫進註解

改動如果推翻了先前的設計、或修的是踩過的坑，**在註解裡留下「為什麼」與「什麼時候」**：

```csharp
// 區塊職責：說明取樣策略改動的原因與影響範圍。
// 物理意義：採樣會影響邊界像素是否混入相鄰資料；此處選用不內插的策略以保持離散 key。
// 數值影響：避免邊界產生無對應資料的中間值，使查詢結果維持可預期。
```

判準：**下一個人可能「順手優化」掉的東西，都要寫明它為何長這樣。**

## 4. 禁止的寫法

```csharp
/* 
不要用這種方式註解!!
*/
```

理由：多行區塊註解在巢狀與 diff 上都容易出事，且不利於逐行 review。一律用 `//` 或 `///`。
