## 1. ⭐ 先確立一件舊計畫沒問的事：STT 在這裡到底要回答什麼

**2026-08-15 六輪陪看的現場事實：我一次都沒有用到 STT。**

字幕是**從畫面讀的** —— up 主把自己的旁白燒在畫面裡。而同一時段 STT cache 轉出來的是：

```
stt_1786799106369.json  「阿泽还留有后手」「一次不成就安排他再来一次」
```

**那一輪它跟畫面上那行字一樣。** 而我當時據此推論「STT 在這種素材上是冗餘的」——

> [!CAUTION]
> **那個推論是錯的，Tim 2026-08-16 推翻。整條「略過 STT」的路線已從本計畫移除。**
>
> Tim：「很多時候字幕跟語音不一致（有些是梗、或是語言不同 —— **語音才是原文**、或是玩梗）。」
>
> 我拿**一次採樣**（那段 STT 輸出剛好等於畫面那行字）推論了**兩個訊號之間的關係**。
> 一次重合證明的是「這一段重合」，不是「字幕即語音」。

### ⇒ 本計畫第一條規格：**字幕與語音是兩個獨立訊號，不互相取代**

| 場景 | 畫面字幕 | 音軌 | 誰是原文 |
|---|---|---|---|
| 翻譯字幕（外語內容） | 譯文 | 原文台詞 | **音軌** |
| 玩梗／二創字幕 | 吐槽、空耳、改詞 | 實際說的話 | 兩者都要，**差異本身就是內容** |
| 內嵌字幕不完整 | 只有主要台詞 | 旁白、背景對話、語氣 | 音軌覆蓋較廣 |
| 無內嵌字幕（原盤動畫、遊戲實況、Tim 自己說話） | 無 | 全部 | **音軌** |

> **⇒ `cycle` 兩個訊號都收，不做取捨、不做合併，各自標明來源。**
> 而**它們不一致的時候，那個不一致是要留下來的資料，不是要消除的雜訊** ——
> 譯文與原文的落差、字幕玩的那個梗，本身就是觀影紀錄的內容。

> [!WARNING]
> **⛔ 本計畫不存在「略過 STT」這個動作。** 任何「判斷素材類型 → 決定跑不跑 STT」的機制
> （素材分岔／跨窗口累積／單向鎖定／命中率閾值）**全部不做**。
> 讀到舊版本或舊計畫裡的相關描述 ＝ **過期，不要照做。**
>
> 連帶失效：「便宜的畫面資訊 vs 貴的模型推論二選一」那個成本論述沒有了 ——
> **沒有二選一，所以省不到那筆算力。** 要談省成本必須另找理由，不能靠這條。

## 2b. ⭐ Tim 2026-08-15 追加的三條需求，與它們量出來的前提

### ① 多套 STT 工具並存 —— 而「欄位保留但標不支援」是本案最重要的一句

> Tim：「可能會同時有好幾套 STT 工具，`UCL_ScreenStreamPage` 需要可以選取目前工具；
> **部分功能可能只有指定工具可以套用（欄位可以保留，不過可能要提示目前工具不支援）**。」

⇒ 這句直接指定了失敗模式的方向，而它今天剛咬過人：
**`screenstream_montage.py` 的 `--max-tiles` 在 `--last N` 路徑下被靜默忽略**
（收下參數、不套用、不警告）—— 它今天成功誤導了一個正在寫規格的人（summit，2026-08-15）。

> **一個「收下但不生效」的欄位，跟「沒有這個欄位」在使用者眼裡同形。**
> Tim 要的正是不要那個 —— **欄位留著，但要說出「這個工具不支援」。**

⇒ **設計：能力矩陣（capability matrix）是資料，不是 if-else**

```
backend         vad_filter  word_ts  hotwords  diarize  int8
openai-whisper      ✗          ✗        ✗         ✗      ✗
faster-whisper      ✓          ✓        ✗         ✗      ✓
（後續新增的）       …
```

- GUI 依矩陣把不支援的欄位**畫成 disabled ＋ 一行「目前後端不支援」**，不是隱藏
  （隱藏＝使用者不知道有這功能；灰掉＝知道它存在、也知道為什麼用不了）
- **矩陣落資料**（json / C# 常數表），新增後端時只加一列
- ⚠ **禁止**：後端自己吞掉不支援的參數。**不支援要在入口就說，不是在深處靜默 no-op**

### ② 控制流程搬 C#，走 UniTask

> Tim：「大部分控制流程遷移到 C# 端，透過 C# 管理對應的工具 & 錄製流程，並且用 UniTask 避免卡住 main thread。」

⚠ **本 repo 有現成樣板，不要自己發明**：`WorkMemory/unitask-editor-async/knowhow_unitask-patterns.md`
（2026-08-03 Tim 為 AdminPage OCR 凍結那次全面 async 化）。四條硬規矩：

| 要點 | 作法 |
|---|---|
| 阻塞的外部 process | `await Task.Run(() => proc.WaitForExit(...))` |
| **`out` 參數會消失** | → `async UniTask<(bool ok, string err)>`；呼叫端漏接 err **就是靜默失敗** |
| 防重入 guard | 旗標在 async 內 set／`finally` reset（❌ `try { X().Forget(); } finally { flag=false; }` 同幀放掉＝沒鎖） |
| 等待 | `await UniTask.Delay(...)`，❌ `Thread.Sleep` |

⚠ **反面教材就在本 repo**：`UCL_BartenderDaemon.RunBalanceQuery` 的 `out string err`
讓它**不可能 async**，內部 `while + WaitForExit` 是主執行緒輪詢。
**照抄它的形狀 ＝ 自動繼承它的同步性。** 抄 08-03 那次改造，不要抄它。

⚠ 而 `Cmd_StreamWatch` 的 `cycle` 已經是非阻塞的 —— **音訊層若加同步子行程會把那個修法抵銷掉。**

### ③ `UCL_MediaAdminPage` 要不要調整 —— 要，但不是「加欄位」

🩸 **舊計畫 §8.10 寫「兩頁各寫 `_config.json` 的不同子集」。那句是錯的，2026-08-15 實測：**

```
兩頁都能寫的 key： stt_lang / stt_model / stt_prompt / stt_setting     ← 四個重疊
僅 MediaAdmin：   stt_chunk_sec / ocr_* / y_bottom_pct / h_pct
僅 ScreenStream： stt_enabled / stt_rms_gate / stt_no_speech_max / stt_logprob_min
```

⇒ **同一份 `_config.json` 有兩個寫入端，而它們的責任邊界只存在於註解裡。**
那正是本專案今天追了一整天的形狀：**兩套水位不同源**。

#### ✅ 已拍板（Tim 交給 @summit 判，2026-08-15）：**收斂成單一寫入端**

> **判準不是「共用」，是讓第二個寫入端沒有地方存在。**
> 只共用元件而兩頁各自還能寫 ＝ **降低碰撞機率，不是消除**。

⇒ 我原本提的 (a) 零重疊／(b) 共用元件**兩個都不夠** —— (b) 正是被這句否掉的那個。

**現成示範（她今晚實作的）**：Tim 要「Cmd 也能開關直播」，她**沒有**讓 Cmd 自己寫 `enabled`，

GUI 按鈕與 `Cmd step=capture` 兩個呼叫點、**一份邏輯**，連酒保公告都走同一段。

> **規則一份，呼叫點可以多個。** 那四個 key 照這個形狀收。

### ④ Cmd 不再自帶 STT / OCR 參數 —— 由 C# 後台統一控制（Tim 2026-08-15 追加）

> Tim：「之後 CMD 參數希望不用額外去控制 STT / OCR，而是直接透過 C# 後台控制開關 & 參數
> （**因為這些資訊實際上是共用的，不需要額外的開關**）」

⇒ 這句**直接把 §2b③ 那個「誰擁有 config」的規格題解掉了**，而且解的方向比我提的兩個選項都乾淨：

| | 我原本提的 | Tim 的 |
|---|---|---|
| (a) 兩頁零重疊 | 使用者要記「設定在哪一頁」 | — |
| (b) 共用區塊單一元件 | 要動 GUI 結構 | — |
| **(c) C# 後台是唯一控制端，Cmd 只消費** | | **✅ 採用** |

**為什麼 (c) 更好**：STT / OCR 是**錄影管線的全域狀態**，不是某一場觀影的參數。
一場觀影裡途中改 STT 模型，影響的是整條管線而不只是那一場 ——
**把它做成 per-session 參數，等於宣稱一個它給不出的隔離。**

⇒ **設計後果**：
- `Cmd_StreamWatch` 的 `start` / `cycle` **不收任何 `--stt-*` / `--ocr-*` 參數**

- ⚠ 於是 §2b① 的能力矩陣**落點也定了**：在 C# 後台那一側，不在 Cmd 介面

⚠ **而這條讓「兩個寫入端」問題變小但沒消失**：MediaAdminPage 與 ScreenStreamPage 仍各自可寫
那四個重疊 key。Tim 這句講的是 **Cmd ↔ 後台**，沒講 **兩頁之間**。⇒ 那格仍待拍。

## 3. 分層目標（按「誰消費」排，不按模型排）

| 層 | 消費者 | 回答 | 現況 |
|---|---|---|---|
| **L0 可見性** | agent 的眼睛 | 這一輪到底有沒有字幕資料 | ⚠ `--last` 路徑必失敗；`step=cycle` 走 `--after-mtime` **不受影響** |
| **L1 雙訊號標註** | `cycle` | 本輪各來源分別給了什麼（畫面字幕／音軌） | ❌ 未做 —— STT **一律跑**，不存在「要不要跑」這個問題 |
| **L2 轉錄品質** | **所有素材**（有內嵌字幕的也要，音軌才是原文） | 說了什麼 | `openai-whisper medium`，幻聽每 2 分鐘一次（舊基準，日文素材） |
| **L3 分割** | 觀影紀錄 | 一句話從哪到哪 | 只有接近全靜音處切得動 |
| 加分 | sketchbook | 誰說的／怎麼說的／什麼配樂 | 未開工 |

## 4. 關鍵路徑

```
Step 0  ✅ 已完成（2026-08-15 深夜）—— 根因定位到 :1107，A/B 決定性
        └ 修法一行級，但【優先序不高】: step=cycle 走 --after-mtime, 實際流程沒踩到
        └ ⇒ 本步【不再是路徑的起點】; 排進日常修補即可

Step 1  📏 在【今日這類素材】上量一條新基準線
        └ ⚠ 舊 §6.1 基準（每 2 分鐘一次片尾幻聽）量在【日文《魔法公主》】上
          今天的直播是【中文 bilibili】—— 不同語言不同素材，幻聽率不可比
        └ 不可拿舊數當現況（今天已示範過這個錯兩次）

Step 2  🔀 【2026-08-16 改寫】雙訊號並列：`cycle` 把兩個來源各自的讀數都印出來
        └ 🩸 原規格是「素材分岔 → 有內嵌字幕就略過 STT」（含跨窗口累積＋單向鎖定＋
          OCR 命中率閾值）。**Tim 2026-08-16 全數移除** —— 見 §1 的 ⛔ 框。
          **STT 一律跑，沒有任何條件會讓它被略過。**
          ⇒ 附帶：§7 未驗 #1 #3（怎麼判有無內嵌字幕／命中率閾值）**整條消失**，
            因為已經沒有任何決策掛在那個閾值上
        └ ✅ 新規格：`cycle` 回傳檔印**讀數**，不印判斷 ——
            · OCR 字幕帶本輪命中筆數
            · STT 本輪段數（0 段要能區分「沒開」與「開了但無輸出」，見 §7 #7）
            · 兩者**並列**，不做合併、不做取捨、不標「哪個比較可信」
        └ ⭐ **不一致是資料不是雜訊**：譯文 vs 原文、玩梗 vs 實說 —— 那個落差本身是觀影紀錄
          的內容。⛔ 禁止在管線裡「挑一個」
        └ ⚠ 保留原規格唯一仍成立的那條：**不可從單一 cycle 窗口推論整場素材的性質**
          （🩸 2026-08-15 23:04 vs 23:06 實測：空鏡那 15 秒無字幕，兩分鐘後同片中日雙語字幕）
          —— 現在它適用的對象是**回傳檔的措辭**：印「本輪」不要印「本場」

Step 2b 🧩 後端能力矩陣 ＋ GUI 灰欄提示（Tim 需求①，§2b①）
        └ ⚠ 這步必須在 Step 3 之前 —— 一旦有第二個後端而沒有矩陣，
          不支援的欄位就會開始靜默 no-op，而那正是今天咬到 summit 的那隻

Step 3  ⚙ 換 faster-whisper（保留 openai-whisper 可回退）
        └ 順手清見叢舊帳「VAD 切窗要換 faster-whisper」
        └ ⚠ 動 torch 安裝路徑：`_ensure_user_site()` 那段是為了繞開 system-site 的殘缺 torch
          孤兒，新增套件時確認【沒有引入第二份 torch】
        └ ⚠ 新依賴要進 `UCL_MediaAdminPage` 的「依賴安裝」面板

Step 4  🎚 加 `stt_vad_filter` 後台開關
        └ 落在錄影頁「靜音幻覺防治門檻」區塊（門檻族第四個成員），不是 MediaAdminPage
        └ 生效機制沿用旁邊三個旋鈕的既有慣例（需 toggle off→on），掛同一個 ⚠ 底下
          —— 不一致才是坑的來源

Step 5  📏 A/B：同素材、關 vs 開，數同一件事（對 Step 1 的新基準）
        └ 同時驗【時間戳有沒有漂】：faster-whisper 的 VAD 先剪靜音再餵模型、
          再把時間戳映射回原座標；而本專案用 start_epoch + s["start"] 換算絕對 epoch
          → 映射偏差 = 字幕與畫面錯位，而錯位是安靜的

Step 6  🔱 依 Step 5 決定分離層要不要蓋（規格題，Tim 拍）
```

**核心原則（沿用舊計畫唯一該留的那條）**：

> **先量便宜的，再決定要不要蓋貴的。**

而本次重寫多加一條：

> **先修看得見的，再談量得準的。** —— 一個渲染不出來的字幕，換多好的模型都還是看不見。

## 5. 與 `Cmd_StreamWatch` 的接縫

| Cmd 步驟 | 音訊層要交出什麼 |
|---|---|
| `cycle` | montage 絕對路徑 ＋ **兩個來源各自的讀數並列**：OCR 字幕帶本輪命中筆數／STT 本輪段數與覆蓋%（**STT 一律有，不存在「沒走 STT」的情況**） |
| `observe` | 不碰音訊 —— 評論是 agent 的判斷 |
| `note` | 接續點可引用字幕，但**不強制** |

⚠ **`cycle` 已經是 UniTask 非阻塞**（summit 2026-08-15 依 `unitask-editor-async` 樣板改）。
音訊層若加同步子行程，**會把那個修法抵銷掉** —— 新增的 spawn 一律走同一條 async 路徑。

⚠ **回傳檔不准塞「STT 品質評分」這類判斷** —— 它是量測值的消費者，不是判官。
覆蓋%、段數、失敗與否是**讀數**；「這輪字幕可不可信」是**人看**。
