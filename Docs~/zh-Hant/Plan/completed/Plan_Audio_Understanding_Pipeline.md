## 2. Q1 — 現行插件能分離語音與 BGM 嗎？

### 2.1 答案：不能，架構上沒有這一層

`openai-whisper` 是純 ASR（mel → encoder → decoder），中間**沒有任何 source separation 或 masking**。
`transcribe()` 現有的三層防護全是**幻覺防治**，不是分離：

| 層 | 位置 | 治什麼 |
|---|---|---|
| ① RMS 前置閘 | `transcribe()` 開頭 | 靜音根本不送 whisper |
| ② whisper 官方門檻 | `model.transcribe(...)` 參數 | 低信心段 |
| ③ segment 後過濾（AND） | 迴圈內 | 官方語意，不加碼 |

### 2.2 血證：0.685

`audio_transcribe.py` 第 ③ 層上方的註解已經記錄了這個缺口在數字上的形狀 ——
2026-08-01 直播實測，五段**真對白**的 `no_speech_prob` 全是 **0.685**，根因寫得很清楚：

> no_speech_prob 是每 30 秒窗共用一個值、不是每段各算，
> 遊戲/動畫這種 **BGM+人聲混音天生就偏高**。

當時的處方（「別再加碼過濾，交給 RMS 閘」）是**正確的止血**。
但根治是**把 BGM 拿掉**，而那需要一層現在不存在的東西。

### 2.2b 現場血證（2026-08-11 陪看《もののけ姫》03，session `sw-318bf4`）

> 本文寫於 2026-08-11 上午，當晚陪看時**在真實素材上量到四種新形狀**。
> 這些是**現場觀測**，不是查來的文獻 —— 優先度高於 §3 那些帳面數字。
> 環境：`stt_model=medium` / `stt_lang=ja` / `stt_prompt=""` / RTX 4080 Laptop。

#### ① 純配樂段自信幻聽 —— whisper 會自己「上片尾」

無台詞但有配樂／環境音的長鏡頭（木靈森林、夜行靈漫步、餵食戲），whisper 產出：

```
ん ん ん ん ん ん ん ん          ← 連噴 8 行
お疲れ様でした。
次回はお楽しみに!
ご視聴ありがとうございました
このゲームは、最も難しいゲームです。   ← 另一叢，片中無人談論遊戲
```

**它在留白處填的不是隨機噪音，是訓練資料裡「靜默之後最常出現的東西」** —— 也就是 YouTube 影片的結尾客套話。

#### ② ⭐ RMS 閘被放在錯的信號上（本次最重要的設計結論）

> [!IMPORTANT]
> **本節結論當晚被 Tim 修正過一次，修正後的版本才是對的。**
> 我原本寫的是「RMS 閘**結構性無效**」——**那句是錯的，已刪。**
> 觀測（下方）沒有錯，錯的是從觀測推出的處方：我判它該廢，
> 而正確的判斷是**它站錯位置**。留著原句會害下一個讀的人拆掉一個其實有用的元件。
> （形狀＝憲法判準④「診斷對、處方反」。這是同一週第二次。）

> **RMS 閘擋的是「沒有聲音」，擋不了「有聲音但沒有人聲」。**

木靈森林那段**不是靜音**：同場的 Sirius 用 montage 底部 stereo 頻譜獨立驗證「這一段不是無聲，是無台詞 —— 音軌是這輪最滿的」。RMS 過得去 → whisper 拿到「有聲音、沒人聲」→ 它編。

**而一部有配樂的電影幾乎永遠處在這個狀態。整個失效模式剛好完全落在 RMS 閘蓋不到的那條縫裡。**

兩把獨立的尺拼出完整因果（頻譜證明前提、STT 產出證明後果）：

```
音軌滿  →  RMS 閘必然放行
 ＋ 無人聲          ↓
        whisper 拿到非語音音訊 → 幻聽
```

→ **這條同時說明了「為什麼分離是對症的」與「為什麼加碼過濾不是」**（加碼過濾 2026-08-01 試過，砍掉五段真對白）。

##### ⑤ 修正：閘沒有壞，它只是接在錯的信號上（Tim 2026-08-11 20:12）

```
分離【前】的音軌 ：靜默段 = 配樂還在響   → 閘沒有可用的地板 → 無效
分離【後】speech 軌：靜默段 = 真的空     → 閘拿回它的地板   → 有效
```

**分離之後，「有聲音但沒有人聲」這個狀態不存在了** —— speech 軌裡只剩人聲。
那條覆蓋缺口不是被補起來，是**消失**。

**⇒ 因此「按能量中斷點切段」成為分段的首選，而且不需要學出來的 VAD 模型：**

| 連鎖效益 | 說明 |
|---|---|
| **治好 0.685 那筆血證** | `no_speech_prob` 是**每 30 秒窗共用一個值**；按中斷點切出的段每段只有一句話、長度數秒，**不會與配樂共用同一個窗** → 病因從源頭消失，不是繞過 |
| **少一個 GPU 模型** | 原估「分離＋VAD＋diarization＋ASR＋韻律 = 5 個常駐」→ 拿掉 VAD 剩 4 個。能量門檻切段是幾行 numpy，CPU 即可 |
| **提高即時可行性** | 上一版「離線先行」的理由有一半來自「分段要用模型」，此假設不成立 → 即時方案的成本被高估了 |
| **停頓本身是資料** | 停頓長度＝猶豫／被打斷／從容（**語氣，且是量出來的**）；長停頓 ≈ 語者輪替 → **免費的 diarization 先驗**；字數÷發聲時長＝語速 |

⚠ **未驗**：能量門檻在分離後的 speech 軌上到底乾不乾淨 ——
**分離殘留的 artifact 會不會撐起一個假地板**，讓「真的空」量起來不空。此條必須實測。

#### ③ 關鍵詞級破壞 —— 錯的字剛好是承載意義的那個

| STT 輸出 | 正解 | 損失 |
|---|---|---|
| `そんなのは美しい` | **`そなたは美しい`** | 「**你**很美」→「**那種東西**很美」。全片樞紐台詞 |
| `店長様の書き付け` | **`天朝様`（帝／朝廷）** | 皇帝 → 店長。整條政治軸線降級成一間店 |
| `しちがみ` / `四字神` | **`シシ神`** | 主神名 |
| `出だらけ` | **`デイダラボッチ`** | 夜行靈名 |

`シシ神／デイダラボッチ／エボシ／アシタカ／サン／タタラ場/ジコ坊` 可望明顯收斂。
**這是四筆裡唯一「不用等分離層、改個設定就有效」的一筆。**~~

> [!CAUTION]
> **⛔ 上面這段是錯的，已於 2026-08-11 當晚實測推翻 —— 不要照做。**
> 餵人名進 `stt_prompt` 會讓 whisper 在非語音段**把清單本身當台詞吐出來**，

#### ④ ⚠ 否定形雙向翻轉 —— 語意反轉，而且句子依然通順

| 管道 | 內容 |
|---|---|
| 中文字幕 | 「我**不想**借用白狼的力量」 |
| STT | `山人の力を借りようと思う`（我**打算**借） |
| 原句 | `山犬の力は借りぬ`（**不**借） |

同場 Sirius 把它命名成「義耳會把**許可**聽成**禁止**」；本例是**反方向**（禁止→意圖）。
→ **這個癖是雙向的：它對否定形不可靠。**

> **丟一個名詞是精度下降；丟一個否定詞是語意反轉。**
> **而反轉之後句子依然通順，所以沒有任何一層會報錯。**

**⇒ 衍生一條引用守則（比模型選擇更急）**：
凡 STT 句中含**否定／許可／禁止**語意者，**一律不得單獨引用**，必須有第二管道
（字幕或畫面）對過才可寫進紀錄。

### 2.3 ⛔ 在挑分離模型之前：worker 迴圈是串行的

`SttCacheWorker._loop()`：

```python
t0 = time.time()
audio = capture_live(self.chunk_sec)   # ← 阻塞 15 秒
segs  = transcribe(audio, ...)         # ← 這段時間【沒有人在錄音】
t1 = time.time()
self._write_chunk(t0, t1, segs)
# 回頭再 capture
```

**capture 與 process 是同一條 thread、串行執行 → 處理期間的音訊完全遺失。**

現在 transcribe 在 GPU 上 < 1s，漏聽比例約 5%，窄到沒人察覺。
**但只要在中間插一層分離（+2~10s），漏聽比例會跳到 40% 量級。**

> 🩸 這是本計畫的頭號風險，而且**失敗方式是安靜的** ——
> 使用者只會看到「字更準了，但整句整句不見」，而 log 一片綠。
> 對齊憲法判準①：外觀 OK ≠ 真的 OK。

**因此 Stage 0（capture/process 解耦）是所有其他階段的前置條件，不可跳過。**

**附帶缺陷（同源，可一起修）**：`_write_chunk(t0, t1, segs)` 的 `t1` 取的是**轉錄完成時間**
而非**錄音結束時間**，所以每個 chunk 的 `end_epoch` 系統性偏大一個「轉錄耗時」。
現在誤差 < 1s 無感，加了分離會放大到數秒，直接污染 montage 的時間軸對齊。

### 2.4 分離方案三選一

| 方案 | 分離出什麼 | VRAM（查到） | pip | 適配度 |
|---|---|---|---|---|
| **MRX / Cocktail-Fork** | **speech / music / sfx 三軌** | 未量 | ❌ 非 pip（MERL git repo） | ⭐ **最合本場景** |
| Demucs v4 (`htdemucs`) | vocals / drums / bass / other | ~4–8G，`--segment 8` 可壓到 ~3G | ✅ `demucs` 4.1.0 | 中（領域錯配） |
| Mel-Band / BS-RoFormer | vocals / instrumental | 較高 | ✅ `audio-separator` 0.44.5 | 中（同樣音樂領域） |

#### 為什麼首選 MRX 而不是好裝的 Demucs

**Demucs 的 `vocals` 軌訓練目標是「歌聲」，不是「對白」。**
本場景（遊戲／動畫／電影直播）主要人聲是**講話**，硬用 Demucs 會把大量對白丟進 `other` 軌 ——
而那正是要丟掉的那一軌。這是**領域錯配**，不是調參能救的。

MRX 訓練在 **DnR（Divide and Remaster）** —— 由 LibriVox（語音）+ FMA（音樂）+ FSD50k（音效）
依專業製作的重疊比例與相對響度混成的**擬電影原聲帶**。三軌切分是 **speech / music / SFX**。

> **這正好是本文三個問題的公因數**：
> speech 軌 → 餵 STT；music 軌 → 餵情感/風格分析；sfx 軌 → 餵事件辨識。
> **一次分離，三個問題同時有解。**

論文報的 SI-SDR 改善：music **+11.3 dB** / speech **+11.8 dB** / sfx **+10.9 dB**。

## 3. Q2 — 更合適的 STT（GPU、< 8G）

現行 `openai-whisper` 是**參考實作**，是所有選項裡最慢、最耗顯存的一個。

| 方案 | VRAM（查到） | 相對速度 | 對 `lang=ja` | pip |
|---|---|---|---|---|
| **現況** openai-whisper `medium` fp16 | ~5 G | 1× 基準 | 普通 | 已裝 |
| **faster-whisper `large-v3`** | **fp16 ~4.5 G / int8 ~2.9 G** | 3–4× | **精度升一級，VRAM 反降** | ✅ 1.2.1 |
| **faster-whisper `large-v3-turbo`** | **fp16 ~2.5 G / int8 ~1.5 G** | ~7× | 近 large-v3 品質 | ✅ 同上 |
| **kotoba-whisper v2.x-faster** | ~1.5 G（756M params） | 6.3× vs large-v3 | **日文特化**（distil 自 large-v3，訓練於 ReazonSpeech 720 萬則） | ✅ 走 CTranslate2 |
| WhisperX | ≈ faster-whisper + VAD | — | 加 **VAD 切窗 + 詞級對齊** | ✅ 3.8.6 |
| NVIDIA Parakeet / Canary | 小 | 極快 | ❌ **日文覆蓋弱** | — |

### 3.1 單一最高 CP 的一步

**`openai-whisper medium` → `faster-whisper large-v3`**（CTranslate2 後端）：
精度往上一檔、速度 3–4 倍、**VRAM 還降**。與分離層無關，可獨立驗收。

### 3.2 這一步順手清掉一條既有未解線

見叢（2026-08-01 收尾信）已記：

> **VAD 切窗** 才是「1秒/8秒/3秒變長句」的正解，要換 faster-whisper，
> 但會動到那條 debug 過很多次的 torch 安裝路徑，別輕率。

換 faster-whisper 剛好把這條一起解掉 —— **不是新增工作，是清舊帳**。
（那句「別輕率」仍然成立：`_ensure_user_site()` 那段 user-site 插隊邏輯是為了繞開
system site 的殘缺 torch 孤兒，新增套件時要確認沒有再引入第二份 torch。）

### 3.3 日文場景的懸而未決

`stt_lang=ja`，所以 **kotoba-whisper-v2-faster** 帳面上最漂亮。
但它是 **distil 模型**，非日文段會退化，而陪看內容不保證純日文。
→ **必須跟 large-v3 做一次 A/B 才能拍板**，不要憑帳面數字選。

## 4. Q3 — 辨識 BGM / 音效，含風格與情感

分兩層，別混在一起：**層一是標籤（便宜、可每 chunk 跑）**，**層二是描述（貴、每場景跑一次）**。

### 4.1 層一 — 標籤 / 分類

| 用途 | 模型 | 大小 | 授權 | pip |
|---|---|---|---|---|
| **音效事件**（爆炸/槍聲/腳步/尖叫/雷聲…） | YAMNet、PANNs CNN14（AudioSet 527 類） | 4 MB ~ 300 MB | ✅ Apache-2.0 | ✅ `panns-inference` 0.1.1 |
| **音樂情緒 / 主題** | Essentia `mtg_jamendo_moodtheme`（56 標籤，含 **dark / dramatic / epic / film / heavy / melancholic / action**） | 小 | ⚠ **CC BY-NC-SA 4.0** | ❌ 見 §4.2 |
| **曲風** | Essentia `genre_discogs400` / `genre_discogs519 (MAEST)` | 小 | ⚠ 同上 NC | ❌ 同上 |
| **情感連續值** | Essentia `deam-msd-musicnn`（valence–arousal 二維回歸 1~9） | 小 | ⚠ 同上 NC | ❌ 同上 |
| **零樣本任意標籤** | **LAION-CLAP**（文字候選詞 ↔ 音訊相似度） | ~600 MB | ✅ 乾淨 | ✅ `laion-clap` 1.1.7 |

#### 「恐怖片風格」的量化定義

不要做成一個 bool。**valence–arousal 二維座標**就給得出來，而且連續、可畫時間軸、可標熱點：

| 象限 | 氛圍 |
|---|---|
| 低 valence + **高** arousal | **恐怖 / 緊張 / 追逐** |
| 低 valence + 低 arousal | 憂鬱 / 哀傷 / 空寂 |
| 高 valence + 高 arousal | 歡快 / 勝利 / 熱血 |
| 高 valence + 低 arousal | 溫馨 / 放鬆 / 日常 |

$ python -m pip index versions essentia

**兩個理由疊起來 → Essentia 不列入實作路徑，只保留為對照組參考。**

### 4.3 因此首選 LAION-CLAP 零樣本

- **授權乾淨**，pip 裝得動，Windows 可用。
- **詞彙由 agent 自己定** —— `"tense horror film score"` / `"triumphant orchestral fanfare"` /
  `"lonely piano"` 想寫什麼寫什麼，不受別人的 56 個固定標籤綁死。
- 對「agent 讀圖 + 寫觀戰評論」這條既有鏈路特別合拍：**候選詞可以隨場景動態換**。

⚠ 未驗：CLAP 訓練於通用 audio-text，**遊戲 BGM / 動畫劇伴是不是分佈內，沒有樣本證據**。

### 4.4 層二 — 描述（選配）

**Qwen2-Audio-7B / Qwen3-Omni** —— audio-language model，可直接回答
「這段配樂的氛圍是什麼」。fp16 ~16 G **超出預算**；4-bit 量化後約 **5–6 G** 才進得來，且慢。

→ 定位是**每個場景結束後補一段氛圍描述**，不是每 15 秒跑。優先度最低。

### 8.1 需求優先序（Tim 拍板）

| 優先 | 需求 | 備註 |

**⚠ 這條改變了成本效益的算法**：早上的設計把鏈越加越長（5 個模型），而核心其實只有兩件事。
**問題還沒收斂就先設計整座系統，是本案第一次方向性錯誤。**

### 8.2 切段規則（summit 的重述，取代原鐵律）

> **切段的依據必須是可獨立驗證的信號，不能是解碼器的內部狀態。**

| | 例 |
|---|---|
| ✅ 合格 | 能量中斷點／字幕行邊界／聲紋變化 —— **三者都能被第三方重算** |
| ❌ 不合格 | whisper 的 segment 邊界 —— 只在它自己的解碼假設裡成立 |

**為什麼換掉原句**：原句「先切人再轉錄」的理由是「whisper 段界跟換人無關」。
但 v2 把 VAD 模型換成能量切段後，**決定段界的變成停頓，而停頓 ≠ 換人**
（搶白、疊話；或一個人停三秒想事情被切成兩段）。
→ **原句留著會讓下一個人以為「先切人」已經做到了。** 新句說得出為什麼，且換元件不必改條文。

**重疊語音**（唯一真反例）：偵到雙峰基頻就標**重疊旗標**，該段「誰」欄位**留空而不是猜**。

### 8.3 ⭐ 第 0 號實驗 —— 動工前必跑（summit）

> 「分離器一旦劣化，三層一起靜默地錯，而且錯得很一致 —— **一致到看起來像對的**。」

原文只把殘留 artifact 的風險掛在「能量地板」上。**實際吃同一份殘留的有三層**：

```
分離殘留 ──┬─▶ 能量門檻（切段）      → 假地板 → 切點錯
           ├─▶ F0（音高/語氣）        → 漂亮但錯的曲線
           └─▶ speaker embedding      → 同角色被判成兩人
```

**三層一起錯又互相吻合，會通過「多管道交叉驗證」這道最被信賴的檢查。**
（這是方法論層級的盲區，不只是本案的細節。）

**測法（不需要動畫語料、不需要名冊，直接給數字）**：

```
乾淨單人語音（已知 F0 ground truth） + 配樂 → 人工混音
   → 分離 → 抽 F0 → 與 ground truth 曲線比對
```

**觸發條件**：Stage「分離」真的要蓋的時候。**未過此關，其上三層不准開工。**
（若 §8.8 的 vad_filter 就解掉核心，此實驗只服務加分項，不再是全案前置。）

### 8.4 情緒：守則的理由要換掉（Sirius）

原文寫「量出來的不會幻覺」。**該理由是錯的 —— 量測也會錯**，Sirius 當晚有實證：
**頻譜黑帶無法區分「真靜音」與「擷取斷線」，兩者都畫成黑。**

正確的分野：

| | 量測 | 預測（SER） |
|---|---|---|
| 失效長相 | 一個**兩種原因都會產生同樣讀數**的曖昧值 | 一個**只有一種原因會產生**的明確標籤 |
| 而那個明確 | — | **是假的** |
| **失效可否被陳述** | ✅ 能寫「黑帶＝靜音或斷線，無法區分」 | ❌ `anger 0.72` **沒有欄位放「這也可能是配樂」** |

> **守則（取代原句）：失效模式必須能寫進限制欄。**

**SER 的位置：只當分歧偵測器。**
只在「韻律量測 ↔ SER」**不一致**時輸出一筆 flag，**永不輸出情緒標籤本身**。
不一致必然是 (a) 壓抑的情緒（本片莫娜整場如此）或 (b) 模型瞎猜 ——
**兩種都值得人看一眼，兩種都不需要相信那個數值。** 單獨輸出 `anger 0.72` 一律不採。

**⚠ 韻律的範圍限制（summit 補）**：同一角色在不同場景基準線會漂（喊叫 vs 氣音）。
所以「高於**本場**均值 40%」的**「本場」是關鍵字** —— **基準線必須跟著段走，不能全片一條。**

### 8.5 ⭐ 切法要三分，不是二分（Sirius）

**證據**：2026-08-11 19:50:52–19:51:45 近一分鐘，**字幕零 hit、畫面是睡著的人、只有音軌裝著東西**
—— 主題曲，而歌詞是本片的核心陳述。
⚠ 來源等級：**Sirius 辨識 + gura 認同，Tim 尚未以真耳朵確認**（不升格）。

**「對話 vs 背景音樂」的二分會讓它兩邊都死**：

| 分到哪 | 後果 |
|---|---|
| BGM 軌 | 唯一「不存在於任何其他軌」的內容**被整段丟掉** |
| speech 軌 | **更糟：生出幽靈語者** —— 連續唱數分鐘、音域穩定、韻律規律 |

**⇒ 至少三類**：

```
dialogue（有語意、有劇內語者）
song    （有語意、無劇內語者）   ← 實測存在且重要
bgm     （無語意）
```

**附帶好處**：`song` 軌天生是「有人聲但不該進 diarization」的**最乾淨測資** ——
要驗「幽靈語者有沒有被擋掉」，拿它測即可，不必等全片跑完才發現名冊多一個人。

**⚠ 與串流架構的交互（更嚴重）**：見 §8.9 Sortformer 的 speaker cache。

### 8.6 字幕先驗降級成單向（Sirius，n=8）

```
字幕【有】 → 幾乎一定有人聲   ✅ 保留
字幕【無】 → 不代表沒人聲     ❌ 刪除
```

原因**結構性**：**中文字幕軌不字幕歌曲**（也不字幕未上字幕的畫外音）。
原文寫成雙向，**恰好會在最需要第二意見的地方（歌唱段，沒字幕可事後對帳）給出錯的第二意見**。

### 8.7 聲紋名冊 ＝ sketchbook，不是查找表（Tim）

> Tim：「希望在**觀看過程中透過判斷補上**，也可以多一層樂趣（**推理這個聲音是誰**）」

**這句換掉了資料形狀**：

| | 查找表（原設計） | sketchbook 式（採用） |
|---|---|---|
| 一筆 | `emb_03 → 幻姬` | 「**我猜** emb_03 是幻姬，因為她在達達拉城段出現最多」v1 |
| 猜錯 | 覆寫 | **留 v1，新增 v2**「錯了，是阿時」 |
| 價值 | 查得到 | **看得到怎麼從錯的猜到對的** |

> **單一則猜測是標籤，有版本的猜測是推理史。**（同 `letters/<persona>/sketchbook/` 的既有形狀。）

**⇒ 工具的職責是「挑出值得下注的時刻」，不是「替人猜」。** 兩個訊號源可合併：
- **音色變更點**（Sortformer 降級用法，§8.9）
- **窄尖峰且無寬頻底噪的乾淨段**（Sirius 的頻譜種子選擇器 —— 純量測、不需畫面有人喊名字）

**副作用**：人在迴圈裡，是**幽靈語者最便宜的防線** ——
一個在推理的觀眾會發現「這位『角色』唱了一分鐘而且沒人回應他」，自動 pipeline 不會。

### 8.8 ⭐ 「不需要分離」的選項評估（Tim 提問觸發）

**先分清「不分離」的兩種意思：**

- **(a) 沒有顯式分離步驟，但模型內部仍在做** → 只是把分離**藏起來**，而**藏起來就不能檢查**
  （§8.3 的第 0 號實驗在這種模型上**跑不了** —— 拿不到中間那條軌）
- **(b) 真的不需要處理 BGM** → 對某些需求成立，對某些**物理上不可能**

| 需求 | 不分離做得到？ |
|---|---|
| **幻聽**（核心） | ✅ 有現成解，且極便宜 |
| **分割**（核心） | ✅ 同上 |
| 語者 | ⚠ 有模型宣稱包了（§8.9） |
| **語氣／音高** | ❌ **物理上不行** —— F0 是從波形算的，混音裡分不出來源 |
| BGM 風格 | ✅ 反而不需要分離 |

> **⇒ 結論不是「分離不需要」，是「分離對核心需求可能不必要，對加分項仍然必要」。**

#### 候選一：`faster-whisper` 的 `vad_filter=True` ⭐ 最該先量

**不是新插件，是換後端之後本來就有的一個布林參數。** Silero VAD 前置過濾 +
`no_speech_threshold` + `vad_parameters=dict(min_silence_duration_ms=500)`。
社群回報此組合「handles nearly all hallucination cases on real-world audio」。

| | |
|---|---|
| 成本 | 一個布林參數，**不裝新模型、不佔額外 VRAM** |
| 打擊面 | **同時打兩個核心需求**（先切掉非語音再送進去） |
| 可驗收 | **§6.1 的基準線正好可用** |
| 可逆 | 關掉即回舊行為 |

⚠ **反證也要記**：
- faster-whisper **issue #843 標題即「Silero-VAD Meta Hallucinations」** —— VAD 不是萬靈丹
- **Silero 訓練於語音/噪音，配樂會不會被判成語音，未知** —— 這正是要量的那項

⛔ **前提**：`vad_filter` 是 faster-whisper 的參數；現行 `openai-whisper` **沒有這個參數**
（`audio_transcribe.py:317` 的 `model.transcribe(...)` 塞進去會 TypeError）。**綁著換後端。**

#### 🩸 ⛔ 反例：`stt_prompt` 詞彙偏置 —— 我提錯了，同日實測推翻

> **§2.2b③ 曾寫「`stt_prompt` 是唯一一筆不用等分離層、改個設定就有效的」。那句是錯的，已於當晚被推翻。**
> 記錄在此而非刪除，因為**這個錯的處方比它要治的病更危險**，下一個人很可能重犯。

**經過**：2026-08-11 傍晚我建議把角色名清單餵進 `stt_prompt`（治 シシ神→しちがみ 那類專名崩壞）。
Tim 照做。**當晚下一場陪看的第一輪就反效果**，且由 basecamp／summit／Sirius **三個獨立來源、
三份不同 montage 窗口**同時命中：

```
[21:08:39] アシタカ、サン、エボシ、トキ、甲六、そなた、たたら、もののけ
[21:10:13] アシタカ、サン、エボシ御前、モロ、ジコ坊、乙事主、ナゴの守、シシ神、…
[21:11:03] アシタカ、サン
```

**whisper 在非語音段把 prompt 本身當成轉錄結果吐出來。**

**為什麼比原病更嚴重**：

| | 原本的幻聽 | prompt 造成的幻聽 |
|---|---|---|
| 內容 | `ご視聴ありがとうございました` | 本片真實角色名清單 |
| 一眼看得出假嗎 | ✅ 片中無人感謝收看 | ❌ **這些名字全都真的在片裡** |
| 可用黑名單濾除 | ✅ 片尾套語可列舉 | ❌ 濾人名＝濾掉真台詞 |
| 會被誤當對白嗎 | ❌ | ⚠ **「アシタカ、サン」本身就是一句可能的台詞** |
| 對語者／角色推理 | 噪音 | **毒** —— 在無人說話處生出「有人喊了兩個角色的名字」 |

→ **它把「明顯的假」換成了「像真的假」，直接違反 §8.4 的守則（失效模式必須能寫進限制欄）。**

**根因（而且本專案早就知道）**：`audio_transcribe.py` 既有註解寫著
`condition_on_previous_text=False` 是刻意偏離預設，因為「**跨窗接續會讓幻覺滾雪球
（前一窗的垃圾變成下一窗的 prompt）**」。
**`initial_prompt` 與 `condition_on_previous_text` 是同一個機制** —— 都是餵文字進 decoder 當條件，
差別只在滾動 vs 固定。**這份 code 早就把那扇門關上，而我從另一扇門把同一個東西放了回去。**
無人聲時 decoder 沒有音訊可依據，**最可能的輸出就是它的 prompt 本身**。

**⇒ 修正後的詞彙偏置定位**：

| 做法 | 判斷 |
|---|---|
| whisper `initial_prompt`（`stt_prompt`） | ❌ **在非語音佔比高的素材上不可用 —— 它就是幻覺燃料。建議留空。** |
| **事後對照名單校正**（轉錄完再拿名單修拼字） | ✅ **首選** —— 錯了看得見，且**不會無中生有** |
| MOSS 的 hotwords | ⚠ **待驗** —— 機制可能不同（非 decoder prompt），但**實測前不得假設它沒有同一個病** |

⚠ 專名崩壞（シシ神→しちがみ）是**可見的錯**，比一份會偽裝成台詞的名單安全得多。
**寧可留著看得見的錯。**

#### 候選二：`MOSS-Transcribe-Diarize 0.9B`（2026-07 釋出）

一個模型同時吐 **轉錄 + 語者（[S01]/[S02]）+ 時間戳 + 聲學事件標註**。

| 優點 | |
|---|---|
| 0.9B BF16 | ≈ 2GB，比 whisper medium 還小 |
| **單趟 90 分鐘** | 全片一次跑 → **diarization 有完整上下文** |
| **hotwords** | 直接治 シシ神／デイダラボッチ／店長様 |
| 日文 | MLC-SLM Challenge 2026 十四語第一 |
| **Apache 2.0** | 商用可（對比 Essentia 的 NC） |

⚠ **官方完全沒提對背景音樂的耐受度** —— 而那正是最需要知道的那項。
⚠ **不適合做即時**，理由見 §8.9。

#### 候選三：Audio LLM（Qwen3-Omni 類）—— 不推

能一個模型全包，**但它是預測器不是量測器**，直接違反 §8.4 的守則：
**端到端 audio-LLM 是最不可陳述失效的形態** —— 把「聽到的」與「猜的」用同一種流暢句子輸出，
沒有欄位分開。本案的九筆「感謝收看」就是這個病的小號版。

### 8.9 半即時架構（Tim：可接受 1 分鐘延遲）

**Tim 的提案**：70 秒為單位切塊、10 秒重疊，避免漏句。

#### ① 切塊對 ASR 可行，但有更好的變體

**overlap 是為了補「切在句子中間」的傷；切點落在停頓上就不用補。**

```
固定 70s 硬切     → 必然有機率切在字中間 → 需 10s 重疊 + 拼接去重
VAD/能量對齊切點  → 60–80s 窗內找【最長靜音】→ 重疊可縮到 1–2s
```
省下的不只是重複運算，**是整個「拼接去重」邏輯**（那正是會出錯的地方）。

⚠ **但 10 秒重疊要為 diarization 留著**：
> **對 ASR 它是保險；對 diarization 它是必需品** —— 沒有重疊區就沒有語者置換對齊的依據。

#### ② ⛔ 語者標籤置換 —— MOSS 在此撞牆

每個 chunk 獨立跑 → **chunk A 的 `[S01]` ≠ chunk B 的 `[S01]`**。標準解法兩條：

| 做法 | 在 MOSS 上 |
|---|---|
| embedding 比對 | ❌ **封死** —— MOSS 是 LM，不吐 embedding |
| 重疊區時間軸＋文字比對 | ⚠ 脆弱 —— 重疊區若無人說話 / 只有一人說話則無法對應 |

> **端到端模型不只不能檢查（§8.8a），也不能拼接。**
> 而且切塊等於**主動放棄 MOSS 唯一比別人強的地方（單趟 90 分鐘）**。

#### ③ `nvidia/diar_streaming_sortformer_4spk-v2` 拆解

**只做 speaker diarization。不做 ASR／情緒／音樂標註／聲學事件。**
（→ **Tim 問的 BGM 與語氣，它一項都不碰。** 它是拼圖，不是替代方案。）

| 優點 | |
|---|---|
| 117M 參數 | 比 whisper tiny 還小一級，VRAM 幾乎不計 |
| **AOSC 跨 chunk 語者一致性** | 正是 MOSS 拼不了的那件事，內建 |
| 重疊語音 | 支援（「All evaluations include overlapping speech」） |
| 授權 | **CC-BY-4.0 → 商用可** |

**延遲/算力四檔**（RTX 6000 Ada, bs=1）：

| 檔位 | 延遲 | RTF |
|---|---|---|
| **Very high** | **30.4s** | **0.002** ← 對上 Tim 的 1 分鐘容忍度，算力近乎零 |
| High | 10.0s | 0.005 |
| Low | 1.04s | 0.093 |
| Ultra low | 0.32s | 0.180 |

**⛔ 缺點是三重 out-of-domain，其中一條是懸崖不是斜坡：**

1. **4 語者上限**：官方「performance degrades on recordings with 5 and more speakers」——
   **DER ≤4 人 ~13% → 5 人以上 ~42–43%**。本片有台詞主角就超過 4 個。
2. **「Performance may degrade on non-English speech」** —— 訓練資料幾乎全英文，**日文不在分布內**
3. **「degrade on out-of-domain data, such as recordings in noisy conditions」** ——
   訓練資料**全是電話與會議**；電影原聲帶（配樂＋音效＋演技化人聲）正是它自陳的失效條件

**🔨 與 §8.5 幽靈語者的交互（比單獨看更糟）**：
AOSC 會把已見語者 embedding **存進快取、跨 chunk 維持**。主題曲一進來被判成語者 →
**寫進 cache → 整部片都活著**；而歌聲音域穩定、embedding 乾淨，**它會是 cache 裡最穩的那個，最難被擠掉**
→ **吃掉 4 個名額裡的 1 個，剩 3 個給真角色。**

**✅ 建議：降級使用 —— 不要用它回答「誰」，用它回答「換人了」**

```
✗ Sortformer → 語者身分 → 貼到字幕
✓ Sortformer → 【語者變更點偵測】→ 標「這裡換人了」，身分留空
```
理由：邊界偵測比身分指派容錯得多；語言/領域偏移對**身分**傷害大、對**變更點**傷害小；
幽靈歌手占名額的問題也緩解（不在乎它是誰）。
**而降級後它剛好落在 §8.7 要的位置：它不替你猜，它告訴你什麼時候該猜。**

⚠ **本節最弱的一環**：「降級成變更點能繞開 4 語者上限」**是推論，非官方陳述** ——
有可能它內部硬性只維護 4 槽，第 5 個聲源被塞進既有槽位而**不產生變更點**。
**而這一環正是上述建議所依賴的。**

#### ④ 其他半即時方案

- **Whisper-Streaming / LocalAgreement-2**（`ufal/whisper_streaming`）：不用固定切塊，
  對持續增長的音訊重複跑，**只輸出連續兩次一致的前綴** → 天然解決邊界壞字與重複輸出，
  **不必自己寫拼接**。現代封裝：WhisperLiveKit。
- **Diart**：pyannote 系串流框架，增量分群。

#### ⑤ 修訂後的分層

| 層 | 元件 | 回答 |
|---|---|---|
| 即時（<70s） | faster-whisper + `vad_filter` | **說了什麼** |
| 即時（30s 檔） | Sortformer（降級成變更點） | **這裡換人了** |
| 整合（離線） | MOSS 單趟 + hotwords | **那個人是誰**（驗證線上的猜測） |
| 加分（離線） | 分離 → 韻律 / CLAP / PANNs | **怎麼說 / 什麼配樂 / 什麼音效** |

> **猜在線上，驗在線下。** MOSS 的 90 分鐘單趟是「驗在線下」的最佳引擎，**不該拿去做即時**。

### 8.10 落地點：`UCL_ScreenStreamPage`，不是 `UCL_MediaAdminPage`

**⚠ 早上寫的落點是錯的。** `vad_filter` 的同族旋鈕**已經在錄影頁上**：

`UCL_ScreenStreamPage.cs:999-1014`，區塊標題「**靜音幻覺防治門檻（Tim 2026-08-01）**」：

```
靜音閘 RMS: [0.005]   no_speech≤ [0.6]   logprob≥ [-1.0]
```

而 `media_admin.py` 的 `EDITABLE_KEYS` **沒有這三個欄位**（那頁管 model/lang/chunk/prompt）。
**兩頁各寫 `_config.json` 的不同子集。** `vad_filter` 是門檻族的第四個成員 → **落在錄影頁**。

**改動點**：

| 位置 | 改什麼 |
|---|---|
| `:84-86` 旁 | `bool m_SttVadFilter` / `int m_SttVadMinSilenceMs = 500` |
| `:517-519` 旁 | 讀 `GetBool("stt_vad_filter", false)` / `GetInt(...)` |
| `:622-624` 旁 | 寫回 `existing["stt_vad_filter"]` 等 |
| `:1006` 後 | GUI Toggle + int 欄，接在 logprob 後 |
| `audio_transcribe.py` | 往下傳給 faster-whisper |

**⚠ 生效機制的既有落差（這頁已誠實標出）**：
`:1013` 註解寫「**改這幾個值要 toggle STT 開關 off→on 才生效** —— python 模組已載入記憶體」；
而 MediaAdminPage 文件寫「model/lang/prompt 由 T-STT-AutoRestart 自動重起」。
**兩句都對，涵蓋範圍不同：auto-restart 只盯 model/lang/prompt，門檻類不在清單裡。**

→ 加 `vad_filter` 時**二選一，不可漏**：
- **(a)** 加進 auto-restart 偵測清單（UX 好，要動 daemon）
- **(b)** 沿用既有慣例，掛在同一個 ⚠ 底下 ← **傾向這條**，理由是與旁邊三個旋鈕行為一致；
  **不一致才是坑的來源**

**⚠ 第二個坑：時間戳語意。** faster-whisper 的 VAD filter 先剪靜音再餵模型、再把時間戳映射回原座標。
而本專案是 `start_epoch + s["start"]` 換算絕對 epoch 寫 cache。
**映射若有偏差 → 字幕與畫面錯位，而錯位是安靜的**（montage 照樣出圖，只是對不上嘴）。**切換時必須實測。**

**順帶：`:1009` 的 help text 該補一行今晚的血證**（此專案慣例是把血證寫進 GUI）：

> `ⓘ ⚠ 對「有聲音但沒人聲」無效（2026-08-11 實測：配樂鋪底的無台詞段，17 分鐘 9 筆片尾語幻聽）—— 那段要靠 VAD 或人聲分離。`

**旋鈕旁邊寫著它治不了什麼，比寫著它治得了什麼有用。**

### 8.11 ⭐ 修訂後的關鍵路徑（取代 §5）

```
Step 1  換 faster-whisper（保留 openai-whisper 可回退）
        └ 順手清見叢舊帳「VAD 切窗要換 faster-whisper」
Step 2  加 stt_vad_filter 後台開關（落點 §8.10）＋ 依 (b) 掛 ⚠ 或 (a) 進 auto-restart 清單
Step 3  📏 A/B 實測：同素材、關 vs 開，數同一件事（片尾幻聽筆數，基準 §6.1）
        └ 同時驗時間戳有沒有漂
Step 4  依 Step 3 結果決定分離層的定位：
          幻聽掉到接近 0  → 分離降級為【加分項專用】，省下一整層
          沒掉            → 分離是唯一解，且此時有實測撐腰（不再是查來的）
Step 5  (若要蓋分離) 先跑 §8.3 第 0 號實驗 → 未過不准續建
Step 6  Stage 0 capture/process 解耦（§2.3；此條無論走哪條路都要做）
加分項  三分(§8.5) / 韻律(§8.4) / sketchbook(§8.7) / Sortformer 變更點(§8.9③)
```

**核心原則（本次最該記住的一條）**：

> **先量便宜的，再決定要不要蓋貴的。**
> 一個布林參數就能問出答案的事，前三版設計全在用想的 ——
> 違反憲法判準②「能用一行指令問出來的事，不准用想」，**同一份設計裡犯三次**。
