# 🎲 自由時間管理頁 (UCL_FreeTimeAdminPage)

> 一句話：**自由時間骰面上有哪些活動、怎麼分組、各自走什麼特殊邏輯，都在這頁改** ——
> 而它改的是 **活動 md 的 frontmatter 本身**，不是另一份設定檔。

**入口**：Editor 控制台 → 🧰 ToolBox → 🎲 自由時間管理（2026-08-18 補上 —— 在那之前這頁
只在 page menu 裡，於是「有這頁」這件事實際上要靠知道才找得到）。

## 為什麼沒有「本頁自己的設定檔」

活動清單的事實來源**只有活動 md 一處**（雙層：UCL_Core 共用層 ＋ 專案層，同 id 專案層覆蓋）。

v1 曾經有過 `AgentCommands/FreeTime/activities.json`，**因雙源同步漂移被廢止** ——
兩個地方各自宣告同一件事時，合併規則會變成看不見的隱式約定，而約定壞掉時不會有人喊。
所以本頁的每個欄位都是**就地改寫 md**（`UCL_AwakeningService.WriteFrontmatterField`，正文不動），
寫完立刻重掃 —— **印 ✓ 不算數，讀回來才算**。

掃描也共用 `UCL_FreeTimeIO.ScanActivities()`，跟 `Cmd_FreeTime` 擲骰是同一份實作 ——
兩份掃描器的漂移症狀是「頁面看到的清單跟實際擲出來的不一樣」，而它不會報錯。

## 操作

### 選活動

上方下拉選單（`PopupGrouped`，分隔符 `/`）選**一項**來編輯 —— 展開面板自帶
**分組切換列 ＋ 搜尋欄**，選項字串以 `<組名>/` 前綴，未分組者落在 `Other` 組：

```
遊戲/📦 chess [Chess]        ← 共用層 / group=遊戲 / kind=Chess
繪圖/📦 canvas-2d            ← group=繪圖
📦 reading                   ← 未分組（下拉裡歸 Other）
🏠 valor-qa                  ← 專案層（同 id 會覆蓋共用層）
（停用）📦 social-chat        ← enabled: false
```

> 分組摺疊走既有的 `UCL_GUILayout.PopupGrouped`，本頁**不自己再寫一套** ——
> 下拉的分組行為該跟其他頁一致，而第二份實作只會慢慢長出自己的脾氣。

> ⚠ 選取記的是**活動 id 不是索引**。Reload 後清單順序會變（新增活動 / 改 id），
> 記索引會安靜地切到另一個活動，而畫面上看起來像什麼都沒發生 —— 接著你的編輯就寫到別人的 md 上了。

### 可編欄位

| 欄位 | frontmatter | 說明 |
|---|---|---|
| 啟用 | `enabled` | 取消勾選＝從骰面下架，檔案保留 |
| **分組** | `group` | 見下節 |
| **特殊邏輯** | `kind` | 見下節 |
| 建議時間 | `min_minutes` | 剩餘時間不足 → 骰面**排尾＋標明**，不隱藏。`0` ＝ 不做時間感知排序 |
| 顯示名稱 | `name` | 骰面主體文字 |
| 做法 | `how` | 一行操作提示 |

文字 / 數字欄走「草稿 → 按**套用**」兩段式，不邊打字邊寫檔（TextField 每幀回傳字串，
直接寫檔會變成每個按鍵都落一次盤）。

### 分組 `group`（Tim 2026-08-18 拍板）

**一份 md ＝ 一件具體活動，分類交給 `group`。**

| 骰面情況 | 呈現 |
|---|---|
| 同 `group` 的活動 | 收成**骰面的同一項**，項底下列出每件具體活動的 id |
| 觸發特殊規則排序（`kind` 條件成立） | **脫離分組成單獨一項**排最前，並印出從哪一組脫離 |
| 沒填 `group` | 自成骰面一項 |

本頁的分組列是**下拉 ＋ 文字欄併存**，這是刻意的：

- **下拉** = 歸到既有組（選項＝當前所有非空 group 去重 ＋ 一個 `(不分組)` 保底項）
- **文字欄「或開新組」** = 開新組；值會先 `Trim()` 才寫

> 為什麼不能只給文字欄：打錯一個字會**安靜地長出一個只有一名成員的新組**
> （`繪圖` vs `繪圖 `），而畫面上兩者看起來一模一樣。
> 為什麼不能只給下拉：那樣永遠開不了新組。

選中活動有分組時，本頁會顯示**該組目前有幾件啟用中的活動**，只有它自己時掛 ⚠ ——
一名成員的「組」在骰面上跟「不分組」是同一個形狀，而建它的人以為自己做了分類。

### 特殊邏輯 `kind`（Tim 2026-08-17 拍板）

下拉選單，選項來自 `UCL_FreeTimeActivityKind` enum：

| kind | 骰面行為 |
|---|---|
| `Default` | 一般活動 —— 不走任何特殊邏輯 |
| `StreamWatch` | 沒開播 → **從骰面隱藏**；開播 → 進優先層並附本場節目名 |
| `Chess` | 有未完成棋局**且對手也在自由時間** → 進優先層（不隱藏，隨時可開新局） |

**為什麼是下拉而不是文字欄**：打錯的標記（`live-strem`）**不會報錯也不會生效**，
只會安靜地退回 `Default`。下拉選單根本打不出那個值。

若 md 是手改的且值認不得，本頁會在該活動下方顯示 ⚠ 提示（用下拉重設一次即可寫回正確值）——
**標記打錯要在設定它的地方就看得到**，不能只在骰面上才顯形。

> 三道處理（可用性隱藏 / 優先層 / 時間感知）的完整語意與判準見
> [`Mechanics/FreeTime_System.md` §4.1.1](../Mechanics/FreeTime_System.md)。
> **新增一種 kind 要同時改 enum 與 `UCL_FreeTimeGating`** —— 一個沒有實作的標記，
> 會讓人以為那裡有一道邏輯。

### `op=pick` 預覽（唯讀）

顯示「agent 挑到這個活動時會讀到什麼」：已選標題、`how`、md 路徑、時間不足提示、
以及**下一步是可代跑還是尚未支援**。

**為什麼需要它**：`how` 在上面是一個單行輸入框 —— 那是**編輯**的樣子，不是**被讀到**的樣子。
兩者不同時，改的人無從判斷自己寫的提示夠不夠用。

> 🩸 這正是 `op=pick` 一度漏印 `op=step` 的那一格：**寫的人看不見讀的人看到什麼**，
> 於是代跑能力隱形了整整一輪，而沒有任何地方報錯。

⚠ 文案與 `Cmd_FreeTimeActivity.OpPick` 的輸出對齊，**那邊改了這裡要跟著改** ——
代價是同一份文案兩處各寫一次；換到的是「不必真的開一場 session 才看得到一行提示」。

### 新增活動

一律建在**專案層**（`<repo>/docs/FreeTime/Activities/`）。共用層屬於 UCL_Core（跨專案），
從某個專案的管理頁往那裡新增等於替別的專案做決定；要改共用活動也走專案層同 id 覆蓋。

欄位：`id` / 顯示名稱 / 做法 / **分組**（留空＝不分組）/ 建議時間。
正文只生一段「待補」佔位 —— **GUI 生得出欄位，生不出「這個活動是什麼」**。
