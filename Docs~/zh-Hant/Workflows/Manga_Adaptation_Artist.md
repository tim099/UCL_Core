# Manga Adaptation — 繪師篇

> 給**作畫**的那一半。分鏡格式與鐵則見 [作者篇](Manga_Adaptation_Author.md)，
> 分工與收播機制見 [總文件](Manga_Adaptation_Workflow.md)。

你的職權是**這個世界摸起來什麼感覺**：分格版面、光影、質感、演出。
分鏡給的是「這一頁要傳達什麼」，不是「這一頁怎麼排」。

---

## 一、圖版人設：三視圖，而且零標註

樣板：`ArtGallery/Comic/template/Character.png`

| 項目 | 規格 |
|---|---|
| **視角** | **正面／背面／側面** 三視（背面不能省 —— 背影是漫畫最常出現的角度之一） |
| **姿勢** | 全身、直立、中性站姿、雙手自然垂下。**不要動態姿勢** |
| **背景** | **純白**。無地面、無陰影、無裝飾 |
| **比例** | 三視**等高等比**，可直接橫向對照 |
| **文字** | **零**。無標題、無標籤、無箭頭、無說明、無色票 |
| **完整度** | 服裝與鞋子畫到底 —— 缺的部分會被每一頁各自腦補一次 |

> [!IMPORTANT]
> **「零標註」是硬規格，不是美觀偏好** —— 因為人設圖會被當成**參考圖**餵進生成器，
> 而它看到的每一個元素都是「這種圖長這樣」的示範。
> 一張佈滿英文標註箭頭的 concept sheet 當參考圖，等於一邊叫模型別畫標籤、
> 一邊拿滿是標籤的圖給它看。**參考圖說的話比 prompt 大聲。**

船同理（舷側／艏／艉三面）。

### 場景與物件設定圖

出現在 **≥2 話** 的場景與帶伏筆的道具**也要設定圖**，規格同樣是**純白背景、零標註**：

| 類型 | 視角 | 額外要求 |
|---|---|---|
| **物件／道具** | 至少兩個角度＋**特徵細節特寫** | **附比例參照**（例：握在手裡的樣子）—— 沒有參照的道具會逐話變大變小 |
| **場景** | 全景 ＋ 主要動線視角（2–3 個） | **固定物的相對位置要一致**（門在哪側、窗在哪、主要家具） |

> 伏筆道具是讀者用來認出「這就是那個」的證據。
> 一件道具第一話入場、第七話兌現，中間隔五話沒人看它 ——
> 它若在那五話裡悄悄變形，第七話的「認出」就不成立，
> 而**這種失效完全無聲**：讀者只會覺得那一格沒有力氣。
>
> 作者的文字設定會標明**兌現時靠哪個細節認出來**，那一項是不准動的；其餘交給你。

## 二、生成手勢

### 1. 掛參考圖 > 文字重建

**畫面上會出現的每一個角色與船，都掛它的人設圖當參考**，再配文字描述。

文字描述必然掉規格（船型／吃水／體型／年齡感），而**參考圖天生帶著所有沒被說出口的細節**。

### 2. 約束有預算

生成模型的注意力有限：**條件愈多，每個條件分到的權重愈少，
而最先被犧牲的是沒有被明講的那些** —— 它們寫在人設卡裡，不在這次的 prompt 裡。

清單分兩層，**別全部塞進 prompt**：

| | 內容 | 放哪 |
|---|---|---|
| **硬** | 船身無文字、不要版面詞與方括號指示 | **進 prompt** |
| **軟** | 專有名詞拼法、姿勢對不對、道具細節 | **靠人審，不靠約束** —— 用眼睛驗比用條件約束便宜 |

> **約束是用來擋住已知會錯的東西，不是用來重述整個世界。** 世界交給參考圖。

### 3. 一次只解一個問題

「清滲漏」「改姿勢」「換構圖」分次做，不要疊成一發 prompt。

### 4. 指示與內容分開送

版面／景別／SFX 的**結構描述不要寫進要求生成畫面文字的那一段**。
判準不是「記得別讓它印出來」（那要人記得，而人會忘），是**結構詞根本不進那一段**。

## 三、畫面上的文字

**字幕與台詞住 `Chapters/NNN.md`，不畫進畫面**（圖文分離）。

| | 規則 |
|---|---|
| ✅ **准** | 招牌上的字、旗幟紋樣等**畫面裡本來就存在**的字；小而貼著畫面的擬聲詞 |
| ❌ **不准** | **船身的船名**（靠旗與徽記辨識） |
| ❌ **不准** | **角色姓名標籤** —— 那是設定集的做法，不是漫畫 |
| ❌ **不准** | **頁碼**（頁次由檔名管） |
| ❌ **不准** | **版面詞**：`TOP PANEL` / `BOTTOM PANEL` / `PANEL 1` |
| ❌ **不准** | **方括號指示**：`[SFX: …]` / `[SOUND EFFECTS: …]` |
| ❌ **不准** | 任何 prompt 原文碎片（`manga panel`、`ink line art`…） |

專有名詞的唯一拼法看該專案的 `NAMING.md`。
**那張表是給 prompt 用的**（讓模型不必腦補），**不是授權把那些字畫上去**。

---

## 四、修正路徑：小問題走原圖微調

審圖抓到問題之後，**預設動作是「拿上一張產出的圖當底，局部修改」**，
不是重下一次 prompt 生成整頁。

| 問題大小 | 動作 |
|---|---|
| **小**（多一行字、道具細節、局部姿勢） | **原圖微調** —— image-to-image／局部重繪，其餘一個像素不動 |
| **中**（整格構圖或動作與分鏡相反） | 只重出**那一格**，其餘沿用；掛人設圖當參考 |
| **大**（整頁方向錯／流程剛變動） | 才重畫整頁 —— 流程剛變時應先走 Stage 3 試畫 |

> **整頁重生成 = 把所有沒寫進 prompt 的細節重新擲一次骰子**，而那些細節上一版通常是對的。
> 為了修一行字，賭掉整頁。
>
> **重生成不是「重做一次」，是「重賭一次」—— 而且賭的是你沒在看的那些欄位。**

---

## 五、交件前

1. **`ls RawImages/`** —— 數量對得上分鏡跨頁數，才可以說「完成」
2. **把圖打開，掃一次「畫面上有沒有字」** ——
   字幕台詞既然住 `.md`，畫面上幾乎不該有文字，**看到字就先當異物**，
   除非它是招牌、旗幟或那個小小的擬聲詞
3. **對一次人設卡** —— 每話開畫前都要，不是只有第一次
4. **合併／拆分了頁面 → 回寫分鏡的頁標題**，否則下一個人會把合併誤讀成漏畫

---

## ⛔ 不可做

- ❌ **人設圖帶標註** —— 它是參考圖，標註會被學走
- ❌ **用文字描述重建角色或船** —— 掛參考圖
- ❌ **把所有規則塞進一發 prompt** —— 沒被明講的細節會先被犧牲
- ❌ **為了小問題整頁重生成**
- ❌ **在畫面上寫船名或掛角色姓名標籤**
- ❌ **在同一話內換畫風** —— 讀者會以為換了作者
- ❌ **宣告「完成」而沒有 `ls` 對過數量**
