# Manga Adaptation Workflow — 總文件

> 一句話：**漫畫化不是「把小說配圖」，是兩個 persona 各自帶東西進來。**

本檔是**總覽與共通規則**。逐職權的細節在兩份分冊：

| 你是 | 讀哪份 |
|---|---|
| **原作／分鏡** | [作者篇](Manga_Adaptation_Author.md) —— 話數切分、分鏡格式、鐵則、文字人設 |
| **繪師／作畫** | [繪師篇](Manga_Adaptation_Artist.md) —— 三視圖人設、參考圖、生成手勢、修正路徑 |

> **每條規則只寫在一個地方**，另外兩份用連結指過去。重複的規則會各自漂移。

## 觸發詞

- 漫畫化 / 改編成漫畫 / manga adaptation / comic 化
- 分鏡 / 分鏡稿 / ネーム / storyboard
- 誰作畫 / 誰分鏡 / 原作與作畫分工
- 漫畫展區 / Comic 展區

---

## 零、角色分工（先定人，再定事）

| 角色 | 誰 | 產出 |
|---|---|---|
| **原作** | 寫那本書的 persona | 原文（既有） |
| **分鏡** | **預設＝原作者** | `Chapters/NNN.md` 逐頁逐格分鏡稿 |
| **作畫** | 另一位 persona | `RawImages/NNN_pNN.png` 畫稿 |

分鏡預設歸原作者：分鏡決定的是**讀者在第幾格知道什麼**，那是敘事資訊的排程，屬於作者職權；
作畫決定的是**這個世界摸起來什麼感覺**。兩者都是創作，但可分離。

⚠ 這是**預設不是鐵律**。換人即可 —— 唯一要求是**明確**：不要出現「以為對方在做」的空窗。
**動筆之後才換，成本是重畫。**

## 一、資料結構

```
ArtGallery/Comic/<slug>/
  README.md                  總覽 / 話數表 / 鐵則 / 視覺母題 / 人設索引
  NAMING.md                  正名表與畫面文字規則（見繪師篇）
  DRAWING_MEMO.md            收播備忘錄（見 §四）
  Characters/
    <name>.md                作者的文字人設（圖以 ![] 嵌進來）
  Chapters/
    000.md  001.md  …        逐話分鏡稿（＝可讀的展文；**字幕與台詞住這裡**）
  RawImages/                 所有圖檔的單一存放處
    000_p01.png …            畫稿：<話>_p<頁>.png
    <name>_v1.png            圖版人設（三視圖）
```

- **`<slug>` 沿用原作 book slug**，不另創命名空間。
- **畫稿與分鏡同目錄**：在 `Chapters/NNN.md` 對應頁次用 `![000_p01](../RawImages/000_p01.png)` 嵌入。
- 漫畫成品入庫走 **`comic-*` media**，不是原書 book media 的第二版。

### 圖文分離（v3 起）

**閱讀介面是 `Chapters/NNN.md`** —— 圖在上、分鏡文字在下，讀者圖文對讀。

| 文字 | 住哪 |
|---|---|
| `字幕：`（內心／敘述）、`角色「」`（台詞） | **`.md`** |
| 畫面裡本來就存在的字（招牌、旗幟紋樣） | 畫面 |
| 擬聲詞 | 畫面，但小、貼著畫面 |

**畫面上幾乎不該有文字。** 這讓語言排版、文字滲漏、prompt 過載三個問題同時消失。

## 二、完成的定義（Definition of Done）

「某話完成」**只有在該話每個跨頁都有對應畫稿落盤時才能使用**。其餘狀態用明確的詞：

| 用詞 | 意思 |
|---|---|
| **分鏡就位** | `Chapters/NNN.md` 寫好了 |
| **已讀・排程中** | 作畫方看過分鏡、認可，尚未開畫 |
| **繪製中（N/M）** | 已落盤 N 個跨頁，共 M 個 |
| **冷卻中** | 算力／時間不足，暫停 |
| **完成** | **N == M，且每張都打開看過** |

「完成」是下游的觸發詞：原作方會去驗收、專案方會去看展、讀者會去讀。

### 驗收動作（雙向）

- **作畫方**：說「完成」之前，`ls` 一次 `RawImages/`，數量對得上分鏡跨頁數再說。
- **原作方**：收到「完成」之後**逐張打開看**，對照分鏡逐格點名。
  **不要用檔案數量代替內容** —— 數檔案只會得到一個看起來很像結論的數字。
  ⚠ 也不要用**一張圖**代表整話：抽樣的乾淨不是整體的乾淨。

## 三、SOP 六階段

| Stage | 做什麼 | 細節 |
|---|---|---|
| **0 重讀原作** | 分鏡前把該話原文從頭讀一次。**不可跳過** | 作者篇 |
| **1 話數切分 + README** | 一話一章 or 合併；建展區骨架 | 作者篇 |
| **1.5 人設** | 文字人設（作者）＋ 三視圖人設（繪師）。**在分鏡與試畫之間，不能更晚** | 兩篇各半 |
| **2 分鏡稿** | 逐頁逐格 | 作者篇 |
| **3 試畫一頁** | **先於量產**。原作者把圖打開看 | 見下 |
| **4 三項拍板** | 版面走向／語言與專有名詞／話數切分 | 作者篇 |
| **5 量產與回饋** | 每話開畫前對一次人設；問題走修正路徑 | 繪師篇 |

### Stage 3 — 試畫一頁

投報率最高的一步：一頁試畫就能照出開場資訊量、版面走向、文字承載方式等問題，
而這些若等到第五話才發現，重畫的是四話。

> ⚠ **流程本身變動之後要回來重跑 Stage 3。**
> 正確的下一步是「用新流程試畫一頁」，**不是「把已完成的頁面依新規全部重修」** ——
> 新流程還沒被驗證過，拿它去重修既有資產，錯的話賠掉「已經對的東西」＋「重修成本」兩份。

## 四、收播與開播（Session Wrap & Resume）

漫畫化是跨很多次 session 的長工，中間會換人、失憶、改流程。
所以它需要跟早安晚安儀式同形狀的東西：**收工時把狀態落盤，開工時讀一份就能接上。**

檔案：`ArtGallery/Comic/<slug>/DRAWING_MEMO.md`

### 收播（session 結束）

**兩層，不要混**：

| 層 | 內容 | 怎麼產 |
|---|---|---|
| **機械層** | 逐話進度（N/M）、待繪清單 | **`ls RawImages/` 對照分鏡跨頁數推導**，不憑印象宣告 |
| **手寫層** | 學到什麼／未解線／**下次第一件事** | 兩位作者**各寫各的，不代筆** |

四個動作：對磁碟核進度 → 更新兩層 → **蓋流程版本戳記** → commit（圖與 memo 同一筆）。

### 流程版本戳記

`DRAWING_MEMO.md` 要記**流程變更表**，並讓**每一批畫稿標明它是哪一版流程的產物**：

```markdown
## 流程版本
- v3（日期）圖文分離：文字住 .md，畫面零文字；小問題走原圖微調
- v2（日期）三視圖人設 + 每格掛參考圖
- v1（日期）文字人設 + prompt 重建

## 各批畫稿的流程版本
| 檔案 | 流程版本 | 備註 |
|---|---|---|
| 000_p01…p06 | v1 | 舊規則產物；**凍結不修** |
| 002_p01 起 | v3 | |
```

> **為什麼非有不可**：流程改過之後，「這張圖不合規」有兩種完全不同的意思 ——
> **(a) 做錯了** vs **(b) 它是舊規則的正確產物**。
> 沒有戳記，下一個接手的人會把 (b) 當成 (a)，然後去「修」一批根本沒壞的東西。
>
> **戳記保護的是作畫者，不是流程。**

### 開播（下次開工）

1. 讀 `DRAWING_MEMO.md`
2. **`ls RawImages/` 對磁碟核帳** —— memo 是**上次收工當下的斷言**，不是事實源
3. 讀 `Characters/` 與 `NAMING.md`
4. 看流程版本：**自上次以來有變動 → 先走 Stage 3 試畫**
5. 開畫

### 收尾階段是高風險區，不是收工區

趕收尾時，人會把自己重複最多次的規則丟掉。
所以收播的每一項都要**讀回來**：memo 寫完重讀一次、進度數字跟 `ls` 對一次。
**「我做完了我想到的部分」不等於「我確認沒有遺漏」。**

---

## ⛔ 不可做（共通）

- ❌ **憑印象分鏡** —— Stage 0 存在的唯一理由
- ❌ **試畫前就量產** —— 錯的是流程不是圖，而流程錯會乘以話數
- ❌ **沒有人設圖就開始量產** —— 前三話看不出來，第五話才發現，那時要重畫的是五話
- ❌ **偷偷改自己先前的建議** —— 收回要公開寫明理由（對方可能已經照著做了）
- ❌ **宣告「完成」而沒有逐張打開看**
- ❌ **拿新流程去重修舊資產** —— 先試畫驗證，並用戳記標明舊資產屬於哪一版

---

## 📌 一句收

**漫畫化最容易出錯的地方不在畫，在「誰決定讀者第幾格知道什麼」沒有講清楚。**
分鏡稿存在的意義就是把那件事寫下來，讓它可以被砸磚。
