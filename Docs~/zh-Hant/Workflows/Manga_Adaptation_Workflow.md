# Manga Adaptation Workflow — 小說漫畫化 SOP

> 一句話：**`Book_Writing_Workflow` 教你寫書，本 workflow 教你把書變成漫畫 ——
> 而漫畫化不是「把小說配圖」，是兩個 persona 各自帶東西進來。**

## 🎯 為什麼存在

2026-08-10，Tim 提議把 summit 的原創小說《桅頂的賭注》漫畫化、由 gura 作畫。
過程中冒出來的問題**沒有一個是「怎麼畫」**，全是流程問題：分鏡誰寫、鐵則怎麼傳達、
資料放哪、哪些決定必須在動筆前定。這些踩過一次就不該再踩，所以 codify。

## 觸發詞

- 漫畫化 / 改編成漫畫 / manga adaptation / comic 化
- 分鏡 / 分鏡稿 / ネーム / storyboard
- 誰作畫 / 誰分鏡 / 原作與作畫分工
- 漫畫展區 / Comic 展區

## 零、角色分工（先定人，再定事）

| 角色 | 誰 | 產出 |
|---|---|---|
| **原作** | 寫那本書的 persona | 原文（既有） |
| **分鏡** | **預設＝原作者** | `Chapters/NNN.md` 逐頁逐格分鏡稿 |
| **作畫** | 另一位 persona | `RawImages/NNN_pNN.png` 畫稿 |

> **為什麼分鏡預設歸原作者**：分鏡決定的是**讀者在第幾格知道什麼** ——
> 那是敘事資訊的排程，屬於作者職權。作畫決定的是**這個世界摸起來什麼感覺**。
> 兩者都是創作，但可分離；混在一個人身上不會更好，只會少一雙眼睛。
>
> ⚠ 但這是**預設不是鐵律**。原作者不想接、或作畫者本來就擅長分鏡，換人即可 ——
> 唯一的要求是**明確**：不要出現「以為對方在做」的空窗。
> （2026-08-10 實例：summit 一開始把分鏡讓給 gura，Tim 補叮指定由 summit 做。
> 　那一次換手成本是零，因為還沒動筆。**動筆之後才換，成本是重畫。**）

## 一、資料結構

```
ArtGallery/Comic/<slug>/
  README.md                  總覽 / 話數表 / 鐵則 / 視覺母題 / 人設索引
  Characters/
    <name>.md                **作者的文字人設**（誰寫的書誰寫；圖以 ![] 嵌進來）
  Chapters/
    000.md  001.md  …        逐話分鏡稿（＝可讀的展文，不只是工作稿）
  RawImages/                 **所有圖檔的單一存放處**
    000_p01.png  000_p02.png …   畫稿：<話>_p<頁>.png
    <name>_v1.png                圖版人設：形象定案
    <name>_v2.png                形象在故事中改變時才有 v2
```

- **`<slug>` 沿用原作 book slug**（例：`summit-masthead-bet`），不另創命名空間。
- **畫稿與分鏡同目錄**：在 `Chapters/NNN.md` 對應頁次處用
  `![000_p01](../RawImages/000_p01.png)` 嵌入 —— VS Code / GitHub 直接點開就能圖文對讀。
- 漫畫成品入庫走 **`comic-*` media**，**不是原書 book media 的第二版**
  （兩者的閱讀進度、心得、輪次各自獨立）。

## 二、人物設定圖（**每一章作畫前都要回頭看的東西**）

漫畫最貴的錯不是畫壞一格，是**角色形象在第五話悄悄變成另一個人** ——
而它不會有人喊，讀者只會覺得「怪怪的」。人設圖就是這件事的唯一解。

### 兩層，兩個作者

| 層 | 檔案 | 誰寫 | 內容 |
|---|---|---|---|
| **文字人設** | `Characters/<name>.md` | **原作者** | 這個角色是誰、身體怎麼用、原作**刻意沒寫**的是哪些 |
| **圖版人設** | `RawImages/<name>_v1.png` | **繪師** | 三面圖 / 表情 / 服裝細節 —— **形象的定案** |

> **兩層都要，缺一不可。**
> 只有文字 → 每一話畫出來都是「另一種合理的詮釋」，五話之後就漂了。
> 只有圖 → 繪師知道長什麼樣，但不知道**哪些細節是有意義的**
> 　（例：手背乾不乾淨、指節有沒有繭），於是會在關鍵格畫出跟主題矛盾的東西。
>
> **文字人設不由繪師寫，圖版人設不由原作者定。** 各自是對方的下游，不是對方的草稿。

### 文字人設要寫什麼（**不是外貌清單**）

外貌交給圖。文字人設寫的是**畫的時候會用到的判斷依據**：

1. **這個人的身體怎麼被使用** —— 職業造成的姿態、慣用動作、視線習慣
2. **哪些細節帶著劇情資訊** —— 「這裡不能畫錯，錯了會破梗」的清單
3. **原作刻意留白的部分** —— 明講「這一項沒寫，繪師畫的就是定案」
4. **這個角色在故事中會不會變** —— 若會，寫清楚**在哪一話之後變成 v2**

### v2 機制：形象只在「故事讓它變」時才換版

- 檔名 `RawImages/<name>_v2.png`，**v1 不刪**（讀者可以回看，而且 v1 仍是前面幾話的正解）
- 在 `Characters/<name>.md` 明寫 **v2 從第幾話起生效、為什麼變**
- 分鏡稿在該話 frontmatter 的 `storyboard_notes` 註明「本話起 <name> 改用 v2」

> 🩸 **2026-08-10 血證（同一話內就漂了）**：《桅頂的賭注》序章六頁，
> P1-P3 是灰調水墨感的霧景與寫實手部，到 P6 變成完全另一種渲染風格；
> 對白語言也從日文變成英文；主角從「蹲在桅頂的瞭望手」被畫成「掌舵的海盜船長」，
> 而她在原作裡**沒有掌過舵**。
> **六頁。不是第五話，是第一話之內。** 這就是沒有人設圖時的預設結果 ——
> 不是繪師不用心，是**沒有任何一份東西讓「上一頁的她」跟「這一頁的她」對得起來**。

> ⚠ **只有故事內的理由能觸發 v2。** 「畫久了手感變了」「這樣比較好看」不是理由 ——
> 那叫漂移，正是人設圖要防的東西。想改就回頭修 v1 並重畫既有頁面，不要偷渡成 v2。
>
> 這跟 reading-library 的**人物看法版本史**是同一個形狀：
> 版本存在的意義是「當時的認知是那樣」，不是「後來覺得這樣比較好」。

### 變體：已經有畫稿時，人設可以「從既有頁面萃取」

若第一話已經畫完，**圖版人設不必從零畫** —— 直接從既有頁面挑出形象最準的那幾格，
整理成 `<name>_v1.png`（Tim 2026-08-10 提）。這條路更快，但有一個前提：

> ⚠ **只有在既有頁面的形象本身是穩定的時候才能萃取。**
> 如果同一話裡形象／畫風已經不一致，萃取只會把「哪一版才對」這個問題往後推 ——
> 那時候要做的是**先由原作與繪師共同挑定一版**，其餘頁面回頭對齊，
> 而不是把最新一張當成人設。

### 每話作畫前的動作

**開畫任何一話之前，先開 `Characters/` 對一次。** 這一步寫進本 workflow 的 Stage 5，
理由跟「重讀原作」一樣：**形象漂移是靠印象作畫的必然結果，不是偶發失誤。**

## 三、分鏡稿格式

### frontmatter

```yaml
title: 第 NNN 話〈標題〉
description: 一句話說這一話在敘事上負責什麼
author: <原作/分鏡> / <作畫>
source: Books/<slug>/NNN.txt
pages: <建議頁數>
storyboard_notes: |
  這一話的任務、節奏建議、以及**本話生效的鐵則**
```

### 正文記法

```
## P3 — 小標（這一頁在做什麼）

**P3-①**〔景別〕畫面描述
　字幕：內心／敘述（方框）
　角色「出聲的台詞」（氣泡）
　效果字：狀聲詞

▸註：給作畫的判斷依據 —— **寫「為什麼」，不要只寫「怎麼做」**
```

**三個記法上的硬規定**：

1. **`字幕` 與 `角色「」` 必須分清楚。** 前者是內心／敘述走方框，後者出聲走氣泡。
   混用會直接改變角色性格（沉默的人變成自言自語的人）。
2. **`▸註` 寫理由不寫命令。** 作畫者要能判斷「什麼情況下可以不照做」——
   只寫命令的分鏡，遇到現場問題時對方只能猜。
3. **不規定分格版面。** 分鏡給的是「這一頁要傳達什麼」，一頁怎麼排是作畫的專業。
   ⚠ 但**作畫合併／拆分頁面之後要回寫分鏡的頁標題**（例：`## P3 & P4 — …`），
   　否則分鏡的頁次與畫稿檔名對不起來，下一個看的人會把「合併」誤讀成「漏畫」
   　（2026-08-10 真的發生過，誤讀的是原作者本人）。

## 四、動筆前必須拍板的三件事

**這三件在試畫之後、量產之前定。晚定的代價是重排既有頁面。**

| # | 要定什麼 | 為什麼不能拖 |
|---|---|---|
| **① 版面走向** | 右開き（右→左）／左開き | **所有伏筆的「先看到哪一格」都跟閱讀方向綁死**。第五話才定，前四話要重排 |
| **② 語言 + 專有名詞對照表** | 全書用哪種語言；船名／地名／自造詞各一個定譯 | 同一個詞在第二話與第六話出現兩種譯法，讀者會以為是兩樣東西 |
| **③ 話數切分** | 一話一章 or 合併 | 影響**讀者手上的編號**；若已有人落盤閱讀心得（`0000`/`0001`），**一致性優先於節奏偏好** |

> 🩸 2026-08-10 血證：summit 先建議「別一比一切」，隔一輪自己收回改成一話一章 ——
> 因為 gura 的閱讀心得已按章落盤。**收回時公開寫明理由，不要偷偷改掉。**

## 五、鐵則機制

原作者對改編通常有幾條「動了就不是這本書」的底線。把它們寫成**鐵則**，並且：

1. **數量壓到 3 條以內。** 超過就不是底線，是遙控作畫。
2. **每條寫「為什麼」**，不只寫「不准」。
3. **標到期日** —— 在分鏡裡指名**哪一話哪一格**是這條鐵則真正生效的地方。
4. **例外要明寫在該格的 `▸註` 裡。** 否則作畫者會以為是原作者漏了，然後「好心」修正。

> 實例（《桅頂的賭注》）：
> - **① 視點不對稱**：背誓者看不見自己的霜 → 霜的鏡頭一律旁觀者視角。
>   **唯一例外在 006-P8②**（父親直視自己的霜），破例本身就是主題，寫死在該格註記。
> - **② 鐘不出聲**：鐘槌落水那兩格不准有狀聲詞。「整本書的重量壓在一個不存在的音效上」。
> - **③ 終章是視線不是臉**：主角是瞭望手，全書替別人看，終章唯一變的是方向。

## 五.五、完成的定義（Definition of Done）

「**某話完成**」這個詞，**只有在該話每個跨頁都有對應畫稿落盤時才能使用**。
其餘狀態一律用明確的詞：

| 用詞 | 意思 |
|---|---|
| **分鏡就位** | `Chapters/NNN.md` 寫好了（原作方的產出） |
| **已讀・排程中** | 作畫方看過分鏡、認可，尚未開畫 |
| **繪製中（N/M）** | 已落盤 N 個跨頁，共 M 個 |
| **冷卻中** | 算力／時間不足，暫停 |
| **完成** | **N == M，且每張都打開看過** |

> **「完成」是下游的觸發詞。** 原作方聽到它會去驗收、專案方聽到它會去看展、
> 讀者聽到它會去讀 —— 三方都會撲空，而撲空的成本比多打四個字大得多。
>
> 🩸 2026-08-10 血證：一天之內「宣告完成 vs 磁碟現況」對不上三次
> （序章 5/5 但被原作誤讀成漏頁、001 是 2/4、002 是 0/9）。
> **三次都不是有人不誠實，是雙方從沒定義過「完成」。**
> 這一節就是那三次的產物。

### 驗收動作（雙向）

- **作畫方**：說「完成」之前，`ls` 一次自己的 `RawImages/`，數量對得上分鏡跨頁數再說。
- **原作方**：收到「完成」之後，**逐張打開看**，對照分鏡逐格點名 ——
  **不要用檔案數量代替內容**（那是 2026-08-10 原作方犯的錯）。

## 六、SOP 六階段

### Stage 0 — 重讀原作（**不可跳過**）

**逐字重讀全書，不靠印象。** 即使書是自己寫的。

> 🩸 血證：summit 差點憑印象直接指出「哪幾場是重點」——
> 那本書是上一輪 session 寫的，腦子裡剩的是輪廓不是原文。
> **拿印象去指揮別人作畫，錯的成本是別人的工時。**

### Stage 1 — 話數切分 + README

先產 `README.md`：話數表（每話標**這一話的敘事軸**）、鐵則、視覺母題、角色設定卡。

**角色設定卡要明寫「原作沒描寫的部分」** —— 那是作畫者的創作空間，
講清楚比留白讓人猜好。（例：「凜的長相原作刻意沒寫 → 作畫者畫的就是定案」。）

### Stage 1.5 — 人設（**在分鏡與試畫之間，不能更晚**）

1. **原作者**寫 `Characters/<name>.md` 文字人設（主要出場角色都要，配角可省）
2. **繪師**照文字人設出 `RawImages/<name>_v1.png` 圖版人設，並嵌回 `Characters/<name>.md`
3. 原作者確認：**不是確認好不好看，是確認「帶劇情資訊的細節有沒有畫錯」**

> 為什麼卡在這個位置：人設要在**量產之前**定案，但也要在**分鏡之後** ——
> 分鏡會決定哪些細節需要被看見（例：某個角色的手背要在第三話被特寫，
> 那隻手就必須在人設圖裡先存在）。

### Stage 2 — 分鏡稿

逐話寫 `Chapters/NNN.md`。除了照搬情節，**至少要做這幾件只有分鏡能做的事**：

- **視點契約**：第一話就立死「讀者能知道多少」，之後所有「他知道而別人不知道」才有重量。
- **跨話的視覺呼應**：伏筆與兌現用**同一個構圖**，讓讀者靠認得出來，不必靠字幕提醒。
- **字體級伏線**：反覆出現的關鍵字（口頭禪、誓詞）指定同一種字體處理。
- **鏡像格**：把主題正反兩面放在同角度不同答案的兩格，並在兩邊互相標註。

### Stage 3 — 試畫一頁（**先於量產**）

作畫者先畫**第一話第一頁**，然後**原作者把圖開來看**（不是看 commit hash）。

> 這一步是本 workflow 投報率最高的一步。2026-08-10 一頁試畫就照出三件事：
> 開場資訊量過多、獨白被放進對白氣泡、版面走向未定。
> **這三件如果等到第五話才發現，重畫的是四話。**

### Stage 4 — 三項拍板（見 §四）

### Stage 5 — 量產與回饋

**每話開畫前先開 `Characters/` 對一次人設。** 不是儀式 ——
形象漂移是靠印象作畫的必然結果，而它不會有人喊。

回饋原則：**分清楚「我要改我的分鏡」「我請你改」「這件現在不決定會很貴」** ——
三種東西混在一起講，對方只會收到「被挑剔」。

能**搬家就不要重畫**：作畫者畫出來的東西若位置錯了，優先找一個它更適合的格子。

## ⛔ 不可做

- ❌ **憑印象分鏡**（Stage 0 存在的唯一理由）
- ❌ **鐵則超過三條** —— 那不是底線，是遙控
- ❌ **只寫命令不寫理由的 `▸註`** —— 現場出問題時對方只能猜
- ❌ **規定分格版面** —— 那是作畫的專業
- ❌ **試畫前就量產** —— 錯的是流程不是圖，而流程錯會乘以話數
- ❌ **偷偷改自己先前的建議** —— 收回要公開寫明理由（對方可能已經照著做了）
- ❌ **沒有人設圖就開始量產** —— 前三話看不出來，第五話才發現，而那時要重畫的是五話
- ❌ **用 v2 掩蓋漂移** —— v2 只能被故事觸發；手感變了就回頭修 v1 並重畫
- ❌ **在同一話內換語言或換畫風** —— 讀者會以為換了作者。語言請在 §四② 先定死
- ❌ **宣告「全數完成」而沒核對** —— 但**核對的對象是內容不是檔名**。
  🩸 2026-08-10 雙向血證：作畫方宣告序章六頁完成、磁碟上五張；
  原作方（我）據此斷定「缺了最關鍵那頁」——**兩邊都錯**。
  真相是 P3 與 P4 被**合併成一個跨頁**（合併版面本來就是作畫的職權），
  而那頁的內容**有畫到**。
  **檔名編號不是內容。** 要確認一話畫完了沒，唯一有效的動作是**把圖打開看**，
  對照分鏡逐格點名 —— 數檔案只會得到一個看起來很像結論的數字。

## 📌 一句收

**漫畫化最容易出錯的地方不在畫，在「誰決定讀者第幾格知道什麼」沒有講清楚。**
分鏡稿存在的意義就是把那件事寫下來，讓它可以被砸磚。
