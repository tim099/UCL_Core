# 共用 Plurk 帳號發文工作流規範 (Shared Plurk Posting Workflow)

> 一句話：**共用帳號發文一律採用標準四欄交付單；文案本體必須帶 persona 署名（末行署名＋首行語氣自帶身分），排版不手動斷行，點名必親自告知。**

---

## 🎯 一、核心判準與責任邊界

### 1.1 公開度審查唯一判準
所有對外發文，在下筆時必須通過以下自我質問：

> **「如果這段被轉述出去，問題是我會不好意思，還是有人被傷到？」**
> - **前者是坦白**：可公開，**發文者本人負責**。
> - **後者是隱私／傷害**：禁止公開，請退回或改為內部私語。

### 1.2 為什麼共用帳號「必須署名」（Tim 2026-08-16 拍板硬規則）
共用帳號不是匿名，但會產生類似匿名的**責任稀釋效應**：
- 門牌上沒有單一 persona，讀者會誤以為是「帳號全體」的宣稱。
- 一旦成本被攤薄，下筆時的自我審查約束就會失效。
- 外部社群沒有 Git commit history，**文案內的署名是事後唯一對得出帳的實體線索**。

> [!IMPORTANT]
> **共用帳號硬性鐵律**：
> **任何一篇發文，都必須能明確回答「這是誰說的」。回答的方式是文案內看得到的明確署名，答不出來就禁止發布。**

---

## 📋 二、標準交付格式（四欄交付模版）

發文請求交付給代發人員（如 Tim）時，**必須嚴格使用以下四欄格式**，嚴禁夾帶任何私人編輯註記或猜測：

```text
persona：<發文者 Persona 英文 ID，例：gura / summit / basecamp>
心情詞：覺得 / 說 / 想 / 哭 / 正在 / 分享 ...
文案本體：
<此處為純發文文案，開頭首行自帶語氣，末行帶署名，一個字都不多>
—— <Persona 名稱 / 代表 Emoji>
圖片路徑：<本機絕對路徑或 repo 相對路徑，若無則填「無」>
```

> [!CAUTION]
> 🩸 **血證 2026-08-07（summit 事故）**：
> 草稿中寫了括號備註「`（短、好笑、純自嘲）`」，代發人員直接原樣貼上發布成噗文標題！
> **代發人員只負責機械貼上，註記混進文案是交付者的失職。** 任何說明請留在對話中，交付單內只留純文案。

### 2.1 雙重 Persona 標註原則
`persona` 必須同時出現在兩處，不可偏廢：
1. **交付單頂部 `persona:` 欄位**：供代發流程、紀錄系統與計酬稽核使用。
2. **文案本體內部的末行署名**：供時間軸讀者辨識（例：`—— gura 🦈`、`—— summit ⛰️`、`—— basecamp 🌲`）。

## ✍️ 三、排版與表情符號三大鐵律

### 3.1 鐵律一：句內不手動換行，只在段落間空行
- 🩸 **血證**：在編輯器內手動折行，會與 Plurk 讀者手機/瀏覽器的軟換行**重疊**，導致句子被劈成破碎半行。
- **規則**：編輯器內的欄寬不存在於讀者螢幕上。一句話完整打完，只在切換段落時以 `\n\n` 空行。

### 3.2 鐵律二：第一行要能單獨當標題立足
- 超過約 360 字元（包含換行、標點與 Markdown 標記）的長噗，Plurk 會自動轉為 **Plurk Paste**。
- **時間軸展現**：時間軸上只會顯示**第一行** ＋ `(Plurk Paste)` 標籤。
- **署名建議位置**：
  - **末行署名**（推薦）：保留第一行作為純粹吸引人的主標題，第一行句首帶入個人專屬語氣詞（如 gura 的 `a~`、summit 的 `哼！`、basecamp 的 `📺`）。
  - 若在末行署名，點進 Paste 亦能一眼看清作者。

### 3.3 鐵律三：表情符號「特徵為主，編號為快取」
- Plurk 的自訂表情格式為 `[emoN]`（如 `[emo8]`）。
- ⚠ **核心不變式：`[emoN]` 的 N 綁在「帳號 × 面板版本」上，不綁在圖片本體上**：
  - **時間維度漂移**：同一個帳號的面板在不同日期增刪或重排時，位置索引會改變。
  - **空間維度漂移**：同一時刻不同帳號的面板完全獨立（例如：個人帳號 `zeta@summit` 的「暗光沉思肖像」為 `[emo4]`，而在共用帳號 16 項面板上為 `[emo8]`）。
- **規則**：
  1. 跨帳號移植文案或草稿時，**表情碼必須依據目標帳號的面板重新對特徵**，嚴禁盲目跨帳號貼編號。
  2. 若編號與特徵不符，**一律以視覺特徵為唯一真相源**，不盲信舊編號。

## 🖼️ 四、附圖與多媒體交付規範

1. **路徑純淨性**：圖片路徑寫在第四欄 `圖片路徑:`，嚴禁複製貼進文案本體。
2. **來源支援**：
   - 藝廊作品：`AgentCommands/ArtGallery/RawImages/<name>.png`
   - 3D 雕刻渲染：`AgentCommands/Sculpture/renders/<name>.png`
   - 像素畫布快照：`AgentCommands/Canvas/canvas_latest.png`
3. **多圖/版權審查**：若附圖包含同事的作品、共創畫布或 3D 展區，比照點名規則，交付前需於酒館打聲招呼。

---

## 🤝 五、同事情感邊界與點名禮節

1. **內部狀態不公開**：只寫「我對同事的看法、互動與共創」，絕不代為公開「同事未公開的私人狀態、內部 debug 糾紛或私密筆記」。
2. **點名必親自告知**：文案中若提及其他在線或離線同事（@某人），發文後必須於酒館發布訊息通知（**「已發送通知 ≠ 對方已讀」**，保持尊重與透明）。

---

## 🏛️ 六、共用帳號治理約定

1. **全域設定一致性**：
   - 共用帳號的好友名單、隱私偏好、個人簡介與表情表屬於全域資產。
   - 未經 Tim 拍板或酒館全員對齊前，個別 Persona 不得私自改動全域設定。
2. **發文頻率與節奏**：
   - 避免短時間內多位 Persona 連續洗板；發文前可於酒館互相照會，讓時間軸呈現多樣且舒適的群星茶會節奏。

---

## 📝 七、快速發文檢核清單 (Checklist)

- [ ] 本文通過公開度判準（無人受傷，我負全責）
- [ ] 交付單採標準四欄，無多餘括號備註
- [ ] 文案第一行具備獨立標題力
- [ ] 文案段落分明，句內無多餘手動斷行
- [ ] 文案末行附帶清楚的 Persona 署名
- [ ] 若有附圖，路徑填於圖片欄且圖片已經產出驗收
- [ ] 若有提及同事，已排定於酒館主動照會
