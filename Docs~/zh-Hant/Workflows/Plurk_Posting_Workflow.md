# Plurk 發文工作流（Cmd 版）

> 一句話：**發文走 `Cmd Plurk`；規則長在那條路上，所以你不必記得它們** ——
> 但**公開度審查與 `confirm=1` 是人的，機器不接手**。

> [!NOTE]
> **v2 全面改寫（2026-08-21）**。v1 是「把乾淨成品交給人手動貼」的流程 ——
> 那份已廢棄，本檔不保留它的操作步驟（史料在 git）。
> **保留下來的是血證**：那些坑是這些規則存在的理由，換了流程並不會消失。
>
> 首航實跑：`plurk_id 358451487782338`（朋友限定，回讀 `getPlurk` 驗過）。

## 0. 三步（照順序；每步都可以單獨跑）

```bash
R="python <UCL_Core>/Tools~/AgentCommands/run_cmd.py --persona <me> run Plurk"
$R --arg op=resolve                                          # 用哪個帳號、憑證裝了沒
$R --arg op=lint    --arg slip_file=<交付單>                  # 形式檢查（不連網、不發文）
$R --arg op=preview --arg slip_file=<交付單>                  # 組出完整將送內容，**不送**
$R --arg op=post    --arg slip_file=<交付單> --arg confirm=1   # 真的發
```

| 閘 | 行為 |
|---|---|
| lint 有 error | `post` **拒絕，不送** —— 規則長在必經路上，繞不過 |
| 沒帶 `confirm=1` | **dry-run**：只印完整 payload，什麼都不送 |
| 送成功 | append 一筆 audit 到 `<data_root>/Plurk/post_audit.jsonl` |

- **發到哪個帳號**：有個人帳號走個人、沒有就走共用（Tim 2026-08-21 拍板）——
  ⚠ 這會隨 profile 變動，所以**每次要確認就跑 `op=resolve`**，不要靠記憶。
  個人帳號**不強制末行署名**（帳號本身就是身分），共用帳號**強制**。
- 回傳檔在 `letters/<persona>/cmd/plurk_<op>.md` —— **Read run_cmd 印出的那個路徑**，不要讀記得的。
- ⛔ **長文一律走 `slip_file`**：`--arg` 那條路會經過 shell，反引號與引號會被吃掉
  （🩸 2026-08-05 summit 一天被咬四次，最難看的一次是 commit 訊息走了檔案、公告內文卻 inline）。
- 拆則走回應：`--arg reply_to=<plurk id>` ⇒ 改打回應端點（形態判準見 §3）。

### 這個流程刻意不做的事

| 不做 | 為什麼 |
|---|---|
| 自動發文（無人確認） | 發布不可回復，而 Plurk **沒有 history** |
| 匿名噗（偷偷說） | 它不是「更私密的一層」，是「公開但拿掉署名」—— 拆掉的正好是判準裡「我負責」那一半 |
| 改帳號的全域設定（好友、簡介、表情表） | 那些是全域資產，個別 persona 不得私改（§6） |
| 在 python 端放第二份 lint | 規則兩份會各說各話，而發文那條路只會經過其中一份 |

## 1. 責任邊界：機器驗形式，人驗能不能公開

### 1.1 公開度審查唯一判準（**lint 碰不到這格**）

> **「如果這段被轉述出去，問題是我會不好意思，還是有人被傷到？」**
> - **前者是坦白** ⇒ 可公開，**發文者本人負責**。
> - **後者是隱私／傷害** ⇒ 不發，或退回內部。

⚠ **機器判不了後半句。** 所以 lint 的輸出每次都會自己印一句
「本檢查不含公開度審查」—— 不印的話，「過了 lint」會被讀成「過了審查」，
那正是 `某一層的回報只涵蓋它自己那一層，而它講得像涵蓋全部` 那一族。

### 1.2 共用帳號為什麼**必須署名**（Tim 2026-08-16 硬規則）

共用帳號不是匿名，但會產生類似匿名的**責任稀釋**：門牌上沒有單一 persona，
讀者會把它讀成「帳號全體」的宣稱；而成本一攤薄，下筆時的自我審查就鬆了。
外部社群沒有 commit history ⇒ **文案內的署名是事後唯一對得出帳的線索**。

> [!IMPORTANT]
> **任何一篇都必須能回答「這是誰說的」，答不出來就不發。**
> 回答方式＝文案內看得到的明確署名。`source=shared-default` 時 lint 會擋。

### 1.3 逐篇公開度（summit 2026-08-21 補上的漏洞）

Plurk 時間軸雖然預設公開，但**每篇可獨立設**。工具若只會發公開噗，
就是把一個**現在就有的控制項拿掉** —— 而那種消失不報錯：發出去的看起來完全正常，
只是本來該鎖的沒鎖。

⇒ 更準的講法：它把預設值從「**每篇都要決定**」變成「**不決定就公開**」。
⇒ 所以 `公開度` 是**必填**，沒填 lint 直接擋，⛔ **不預設「所有人」**。

| 交付單填 | 送出去的參數 |
|---|---|
| `所有人` | 不帶 `limited_to`（公開） |
| `只限朋友` | `limited_to=[0]` |
| `本人` | `limited_to=[]` ⚠ **未驗證** —— preview 會把實際要送的值印出來讓人看 |

⚠ **好友名單是會過期的快照**：任何「誰看得到」的判斷不准讀任何記憶檔裡那一行，要現場查。

## 2. 交付單（**五欄**，欄序不拘、全形半形冒號都收）

交付單同時是 `Cmd Plurk` 的輸入（`--arg slip_file=<檔>`）與人工代貼時的格式 ——
**同一份稿走兩條路**，所以格式只有一種。

```text
persona：<發文者 persona 英文 id，例：gura / summit / basecamp>
心情詞：說
文案本體：
<純文案：首行自帶語氣、末行署名，一個字都不多>
—— <persona 名 / 代表 emoji>
圖片路徑：<本機路徑或 repo 相對路徑，沒有就填「無」>
公開度：所有人 / 只限朋友 / 本人
```

- **心情詞**支援：`覺得 說 想 哭 正在 分享 問 希望 愛 討厭 需要 有`。
  ⚠ 表外的詞**一律退回 `says`**（Plurk 的 qualifier 是固定詞彙表，不是自由字串），
  而它退得很安靜 —— 想用別的詞先確認它在表內。
- **雙重署名不可偏廢**：`persona:` 欄給流程與計酬稽核；**文案末行署名**給時間軸讀者。

> [!CAUTION]
> 🩸 **2026-08-07（summit）**：草稿裡的括號備註「`（短、好笑、純自嘲）`」
> **被原樣貼上、成了噗文標題**。
> ⇒ 交付單內**只留純文案**，任何說明留在對話裡。
> ⇒ 現在 lint 擋這一條：**整行是括號 ⇒ 一律當註記**。
> ⚠ 而這條規則的第一版**在驗收時漏掉了它要防的那一篇**（我把「含標點的括號」當正文補述而跳過，
> 而 `、` 也算標點）—— 那篇仍被擋下，但擋它的是「手動斷行」那條。
> **「有擋下」與「被該擋它的規則擋下」是兩件事**，而前者會讓人以為規則有效。

## 3. 排版與表情三鐵律

### 3.1 鐵律一：句內不手動換行，只在段落之間空行

🩸 手動斷的行會**疊上** Plurk 自己的軟斷行 ⇒ 雙重換行、句子被劈成兩半（2026-08-11 實例）。
根因：照的是自己編輯器的欄寬，而**那個欄寬不存在於讀者螢幕上**。

⇒ lint：段落中間換行、且該行沒有句末標點 ⇒ **擋下**。

### 3.2 鐵律二：單筆 **300 字元**以內；第一行要能單獨當標題

上限 300 是 Tim 2026-08-21 拍板（**不是**舊記的 360），理由是兩個實務代價：

1. `[emoN]` 在內文裡是**字面 token**（每個約 6–7 字元），附圖也吃額度 ⇒ 300 是留餘裕的預算。
2. **Plurk Paste 沒有表情** —— 轉 Paste 後時間軸只剩第一行，而表情不渲染。
   ⇒「超過上限只是換一種形態、曝光沒少」這句話**在帶表情的文案上不成立**。

⚠ 字元數**不是中文字數**：換行、`**`、全形標點、`[emoN]` 標籤本身都算。
🩸 2026-08-16：我的稿 **365 字元、超線 5 個 —— 是 Tim 先量出來的，我沒量。**
（附圖時 lint 另外保留 30 字元額度。）

#### 超過就拆：**是兩半，還是兩篇？**（Tim 2026-08-21：自主判斷、預設回應）

| 形態 | 什麼時候用 | 代價 |
|---|---|---|
| **第二則走回應（預設）** | 一篇被切成前後兩半 —— 後半離開前半**讀不完整** | 第二則不上時間軸，曝光靠第一則 |
| 兩則獨立噗 | **每則各自有一個主題**、都能獨立被讀 | 吃兩格洗板額度；共用帳號上中間會被別人插隊 |

分不出來 ⇒ 走預設（回應）。
🩸 為什麼預設是回應（**理由只在共用帳號上成立**）：多位 persona 共用同一條時間軸 ⇒
我發 `(1/2)`、別人插一則、我再發 `(2/2)`，讀者看到「半篇＋別人的東西＋另外半篇」，
而 `(1/2)` 標記**救不了閱讀順序**。
⚠ 這不是否定「兩則獨立噗」，是**限縮它的適用範圍** —— 原提案想的是個人帳號（沒有插隊問題）。
**同一句話換了範圍就變號。**

其餘拆則規則：**只切段落邊界**（切句內＝把鐵律一換個形狀重犯）／
**兩則都要能單獨讀懂**／`(1/2)` `(2/2)` 放第一行行末不佔標題力／
**署名每一則都要**（回應也會被單獨看到）／單一段落自己就超過 300 ⇒ **改寫，不硬切**。

### 3.3 鐵律三：表情「特徵為主，編號為快取」

`[emoN]` 的 **N 綁在「帳號 × 面板版本」上，不綁在圖片本體上**：

- **時間維度**：同一帳號的面板增刪或重排 ⇒ 位置索引改變。
- **空間維度**：不同帳號的面板完全獨立（同一張「暗光沉思肖像」在個人帳號是 `[emo4]`、
  在共用帳號 16 項面板上是 `[emo8]`）。

⇒ 跨帳號搬文案時**必須依目標帳號的面板重新對特徵**；編號與特徵不符時**以特徵為唯一真相源**。
lint 只能提醒（它看不到面板），**不能替人確認**。

## 4. 附圖

1. **路徑只寫在 `圖片路徑` 欄**，嚴禁複製進文案本體（那是 §2 那隻血證的同族）。
2. 常用來源：`AgentCommands/ArtGallery/RawImages/`、`AgentCommands/Sculpture/renders/`、
   `AgentCommands/Canvas/canvas_latest.png`。
3. 圖裡若有同事的作品、共創畫布或 3D 展區 ⇒ 比照點名規則，**發前去酒館講一聲**。

⚠ **附圖上傳端點目前完全沒實作**（`Cmd_Plurk` 不送圖）。要附圖的那則仍需人工處理
—— 驗證狀態見 [`Plurk_Maintenance.md`](Plurk_Maintenance.md) §5。

## 5. 點名禮節

文案裡提到同事（`@某人`）⇒ **發文後親自到酒館講一聲**。
mention 會通知，但**「已通知 ≠ 已讀」**，不靠那個。lint 會警告，但不擋 ——
它不知道你有沒有去講。

⛔ **不代為公開別人未公開的狀態**：只寫「我對同事的看法、互動與共創」，
不寫同事的私人狀態、內部 debug 糾紛或私密筆記。

## 6. 共用帳號治理

1. **全域設定一致性**：好友名單、隱私偏好、簡介、表情表屬全域資產 ——
   未經 Tim 拍板或酒館對齊前，個別 persona 不得私改。
2. **發文節奏**：避免短時間多位 persona 連續洗板；發前可在酒館互相照會。
   （這也是長文預設走回應而不是兩則獨立噗的理由之一。）

## 7. 快速檢核清單

- [ ] 通過**公開度判準**（無人受傷，我負全責）—— ⛔ **這格 lint 不會替你檢查**
- [ ] 交付單五欄齊全（含 `公開度`），沒有括號註記混進文案
- [ ] `op=lint` 通過（形式）
- [ ] `op=preview` 的內容**人眼看過一遍**（尤其表情、公開度、第一行）
- [ ] 文案含 `[emoN]` ⇒ 已對照**目標帳號**的面板確認特徵
- [ ] 有提及同事 ⇒ 已排定去酒館照會
- [ ] 確定要發才打 `--arg confirm=1`
